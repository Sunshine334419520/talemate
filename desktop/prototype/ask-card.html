ask-user · 提问卡片

搭档的提问卡

现在的提问卡能把问题递到你面前，也能把搭档永远挂在那里。这个方案把它改成一套有超时、有跳过、有回看的对话契约：卡片占住输入框的位置，超时只是 pending，收起不等于回答。

位置 卡片占住输入框的位置

打开时输入框让位，像底部弹窗一样贴在中栏底部；对话仍然可以读。收起后输入框回来，提示条还在。

超时 pending 不是同意

到点搭档停下这一轮，问题还在。你回来答，答案作为一条新消息送达，不由沉默替你做决定。

收起 收起不是回答

收起只把卡片折成一条提示，不发送任何内容。只有「跳过」或「提交」才产生答案。

原型

先看它怎么动

下面是一个可点的原型：两题翻页、推荐预选、多选、自定义、收起、超时、回看。打开时卡片会占住输入框的位置，像底部弹窗一样贴在中栏底部；收起后输入框回来。计时器缩短到 90 秒；点「跳到超时」可以直接看 pending。所有状态都在这一页里，不会发出去。

键盘：↑↓ 移动选项，Enter 提交或跳到第一道没答的题，Esc 收起；输入框里 Enter 继续、Shift+Enter 换行。输入法组合中的 Enter 不会提交。

1 推荐只是预选

第一项带「推荐」时会先勾上，但不暂停计时、不提交。你可以直接换。

2 打开时输入框让位

卡片贴在底部，占住输入框的位置；收起后输入框回来，草稿和剩余时间都还在。

3 超时是 pending

到点搭档先停下，问题仍在。你回答之后，答案作为一条新消息送达。

4 最后一题不自动提交

点击只选中。提交要一次明确的动作；Enter 是键盘用户的快捷路径。

契约

契约比样式重要

DSH 的弹窗好看是表面，真正难的是它背后的状态。直接抄 UI，会得到一个“会卡住搭档的漂亮弹窗”。这里只抄契约，并且按 talemate 的形状落。

线上形状保持极简

// 模型给的：1–3 题；options 可选；multi_select 默认 false
interface AskQuestion {
  id: string;                    // 稳定 id，答案里回传
  header?: string;               // 卡片左上角的小标题
  question: string;              // 用户语言；正文走 markdown
  options?: { label: string; description?: string }[];
  multi_select?: boolean;
}

// 用户回的：selected 为空且没有 custom = 明确跳过
interface AskAnswer { id: string; selected: string[]; custom?: string }

// 交付层回给工具的：pending 不是答案，是“这一轮先停”
type AskOutcome =
  | { kind: "answered"; answers: AskAnswer[] }
  | { kind: "pending"; callId: string }
  | { kind: "cancelled"; reason: "no-answerer" | "aborted" };

状态机：收起不是终态

open ──提交──────────────────> answered
 ├──逐题跳过───────────────> answered（该项 selected: []）
 ├──收起───────────────────> open（不发任何消息）
 ├──超时 / 稍后────────────> pending ──回答──> answered（作为新回合送达）
 └──没有回答方 / 中止──────> cancelled

回答只走一条路

此刻回答去哪结果
工具调用还开着resolve 那个等待中的 Promise同一回合继续
已经 pending追加一条 answer_to_pending_question 用户消息开一个新回合
callId 不认识拒绝，回 stale卡片显示“这个问题已经结束了”
子代理调用question: deny返回自愈文案，不弹用户的脸

提示词：行为约定写在字段里

推荐项不另加 recommended: true——UI 只认 label 末尾的「（推荐）」。这是模型和界面之间唯一需要约定的写法。工具 description 管“怎么问”，system 里那一段管“什么时候不该问”。

# prompts/tools/ask-user.txt
Ask the user 1–3 concise, self-contained questions when an answer cannot be inferred
from the project or the conversation: a creative choice, a missing preference, or a
decision between options with real trade-offs.

Each question needs a stable id. Offer 2–5 options when choices exist; put your
recommendation first and end its label with （推荐）. Each option's description says
what it buys and what it costs. Use multi_select only when the choices are not
exclusive. The user may type a custom answer or skip a question; a skipped answer is
empty, not consent.

timeout is the seconds to wait for the whole batch (default 120); use -1 only when
you cannot proceed without an answer. A timeout returns pending, not skipped: the
turn ends, the user can still answer, and you must not act as if they agreed.

# prompts/mate.system.txt（新增一段）
# Asking
Ask only when the answer cannot be read from the project or inferred from what the
user said. Use ask-user for creative decisions, never as a permission gate. At most
3 questions per call, 2–5 options each; lead with your recommendation and say what
each option costs. If the user skips or the question times out, that is not consent:
do not act on silence.

持久化：两个事实，不是两份状态

已提交的提问落在 tool part 的 ask 记录里；迟到回答落在用户消息的 answersTo 里。界面的“还开着哪些问题”由两者投影出来，不另存一份问题状态。唯一额外的是 .talemate/sessions/<id>/pending-ask.json：它只覆盖“提问已经开始、助手消息还没提交”那段窗口，是 write-ahead 记录，不是第二份真相。

现状

现在的三个洞

不是样式问题。现在的 ask-user 是一张卡、一个问题、一个永不超时的 Promise；窗口一关，搭档就卡在工具调用里，而且不会报错。

现在会发生什么方案里改成
窗口关掉 / 刷新ask() 的 Promise 永远不 resolve，搭档卡在工具调用里没有回答方立即失败；主进程持有截止时间；草稿落本机
只有一张卡、一个问题长问题把按钮顶出屏幕；多选和自定义没有位置卡片限高、内部滚动；1–3 题翻页；单选 / 多选 / 自定义同一套
没有跳过和超时用户只能答或不管；沉默被当成默认answered / pending / cancelled 三态分离；跳过是显式空答案
界面

十条规则，按优先级

前六条决定“好不好用”，后面是打磨。每一条都能在原型里点到。

1 · 卡片占住输入框的位置

像底部弹窗一样贴在中栏底部，打开时输入框让位，不做独立模态框。对话仍然可以读。

2 · 一题一页，提交整批

1–3 题用翻页器走；不把所有题垂直堆满屏幕。

3 · 单选点击前进，最后一题不自动提交

多选只切换。提交永远是一次明确的动作。

4 · Enter 与输入法

输入框里 Enter 继续、Shift+Enter 换行；组合中的 Enter 只确认候选。

5 · 卡片限高

标题、翻页器、提交按钮固定；长问题和长选项共享内部滚动区。

6 · 每个会话 + 每个 callId 一份草稿

切会话、刷新页面、重开应用都能恢复；只在本机，不跨设备。

7 · 倒计时会停，但不会停死

聚焦暂停；首次编辑或「慢慢回答」转不限时；「稍后回答」立即转 pending。

8 · 结束时是只读卡

已回答 / 已跳过 / 已超时都能回看；跳过的那题说明“当时跳过”。

9 · 问题正文 markdown，选项 label 纯文本

复用助手输出的渲染原语；选项不做富文本，避免把答案变成另一段正文。

10 · 收起后输入框回来

提示条一直在；工具行和提示条都能重开卡片，草稿和剩余时间不丢。

验收

八个探针，过了才算一样好

前五个是产品行为，后三个是工程边界。都能在离线测试或桌面自检里跑，不需要模型。

场景期望
用户离开 2 分钟到点返回 pending，搭档停下这一轮；问题仍可回答
点「跳过」该项 {selected: []}，其余答案保留，批次正常返回

落地

分三步落，每步都能用

第一步先把卡片和契约做对；第二步才上计时与持久化；第三步收口与探针。不要一次把 8 个场景全写完。

第一步

卡片 + 单题/多题

递归 JSON schema、AskQuestion / AskAnswer、工具校验、runner 的 ask 与 halt、桌面 dock、翻页、跳过、自定义、收起/重开、CLI 批量输入。

  • 覆盖 80% 场景
  • 没有回答方时 fail closed
  • 先不碰超时
第二步

计时 + pending

主进程截止时间、pending 三态、稍后回答、迟到回答走新回合、草稿持久化、只读回看卡、system 里的未答问题注记。

  • 这一步最容易被漏掉
  • 也是“不卡住搭档”的关键
第三步

收口 + 探针

confirm 的窗口丢失改为 fail closed；多个 pending 的队列；键盘与无障碍；八个探针进 CI；docs 与 prompts 对齐。

  • 探针不需要模型
  • 子代理 deny 继续由测试钉住

明确不做（这一版）
  • 不给 schema 加 type: "confirm" | "choice" | "multi" | "form"。形态由 options + multi_select 推出来，未知形态退化成通用选项列表。
  • 不做独立模态框，也不把提问塞进右栏。它是对话的一部分。
  • 不单独存一份“问题状态”。未答问题从消息投影；pending-ask 只覆盖提交前的窗口。
  • 不把 confirm 合并进提问卡。沉默时两者的安全默认相反（ask → pending，confirm → 拒绝），答案形状与副作用也不同；共用视觉外壳，不共用契约。
  • 不做双窗口。协议已经用 callId + stale 准备好了，这一版的壳只有一个窗口。
  • 不做点击即提交。点击只选中；Enter 是键盘用户的快捷路径。
