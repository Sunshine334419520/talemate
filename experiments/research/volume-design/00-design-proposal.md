# 卷与序列：从“轮廓”到“契约”

> **职责**：回答“一卷/一个序列到底该写什么、写到什么程度、怎么让 AI 据此生成更好的下一层”。
> **读者**：要改 `framework/design_spec.ts` 的卷纲/序列纲规范、`prompts/planner.system.txt`、`prompts/tools/propose-plan.txt`，以及 `docs/outline.md` 的人。
> **状态**：已落地（2026-10-19）。六格、序列契约块、标题改名、卷末结算、状态软约定均已实现；本文保留研究依据与取舍，供后续回看。研究依据见同目录 `01`–`04` 四份报告。
> **相邻**：`docs/outline.md`（现有情节层说明）· `docs/chapter-planning.md`（章生产）· `docs/state.md`（承诺账的实际状态）

---

## 0. 一句话

**卷不是一个更大的章，序列也不是一段更短的卷。**

两者都是**契约**，只是尺度不同：

| 层 | 它回答的问题 | 它约束什么 | 它留给下一层的自由 |
|---|---|---|---|
| **卷** | 这一阶段，主角和世界必须发生什么不可逆的变化？ | 独立问题、入口/出口状态、对手、旧债/新债、禁揭、节奏 | 分几个序列、每个序列怎么走、具体事件 |
| **序列** | 这一小段自己的故事是什么？ | 单元问题、入口/出口、2–4 个转折、承诺、约束 | 具体场次、对话、谁先出场、怎么写 |
| **章** | 这一章让什么发生变化？ | 本章价值变化、章末读者问题、不能提前兑现 | 节拍、场景、动作、文风 |

**事件永远可以换；被约束的是状态转移、转折的功能、承诺的兑现和不变量。** 这就是“功能 + 契约”的全部含义。

这套设计以**男频/女频网文连载**为主，兼顾出版向；它不假设每卷等长，也不假设“三卷 = 三幕”。网文的结构卷常见 10–30 万字（约 30–100 章），卷内常见 3–6 个序列；这些是经验区间，不是配额。

```
卷契约：这一阶段要回答什么、结束时什么必须为真
   │
   ├── 序列 1 契约：这个单元的问题、转折、出口
   │      └── 章规划：这一章兑现哪一段、改变什么、留什么钩子
   ├── 序列 2 契约：……
   └── 序列 3 契约：……
```

**卷纲推荐六格**：位置 / 目标与阻力 / 承诺 / 节奏与情绪 / 卷末状态 / 本卷的序列。新增的“本卷的承诺”是网文连载最需要、现有五格最容易漏掉的一格；不想要六格时，也可以把承诺折进“位置”和“卷末状态”（见 §4）。

卷纲不是“剧情梗概”，它更像**给序列规划者的任务书**；序列纲不是“情节摘要”，它更像**给章规划者的工作单**。

## 1. 研究结论（只保留会影响设计的）

四份报告（中文网文工艺、西方结构、AI 长篇生成、作品拆解）交叉后，下面几条最稳：

1. **卷 ≠ 幕。** 幕由重大价值反转折定义，卷是阅读/生产单位。一个卷可以包含一个完整三幕，也可以只是更大一幕中的一段；不要做“三卷 = 三幕”的对称映射。
2. **卷的判据是“不可逆变化”，不是字数、章数或地图。** 一卷结束时，力量/身份/关系/认知/资源/地理六轴中至少一轴必须发生不可逆变化；只写“打败了 X”是事件，不是状态。
3. **一卷 = 一个独立问题 + 一次不可逆变化 + 一笔旧债结清 + 一笔新债开立 + 一个更大的问题。** 删掉本卷，主线几乎不变，它就是注水。
4. **序列是规划的主单位，章只是交付单位。** 序列必须有自己的戏剧问题、入口/出口和至少一个不可逆转折；一个序列可以跨多章，一章也可以只覆盖序列的一部分。
5. **卷与序列的数量是经验区间，不是配额。** 中文网文的结构卷常见 10–30 万字（约 30–100 章）；一卷常见 3–6 个序列。超过 8 个序列先想是不是该拆卷，少于 3 个先想每个序列是否撑得起一个完整弧。
6. **契约与清单的区别是承重墙。** 契约约束“结束时什么必须为真、过程中必须付出什么”；清单约束“先发生 A 再发生 B”。AI 长文需要前者；后者会把写手变成填表机器，并制造重复。
7. **承诺必须显式记账。** 即使上下文里有，模型也会忘记回收。承诺账要有：承诺什么、在哪埋下、计划何时兑现、当前状态、正文证据。**计划在 design，实际状态在 state。**
8. **知识边界是结构，不是文风。** 悬疑、误会、戏剧反讽都依赖“谁知道什么/谁不知道什么”。卷末和序列出口都要写知识边界，章规划不能让人物使用他不该知道的信息。
9. **模板只能做诊断，不能做生成配额。** 三幕比例、15 beats、每卷 8 序列、每卷都“全盘皆输”——这些是常见分布，不是必须。硬化成检查项会生产对称、可预测、充满填充物的卷。
10. **规划粒度甜点在“场景以上、事件以下”。** 卷约 5 个宏观阶段；序列 2–4 个 turn；章 2–5 个 scene beat。再细就会僵硬，再粗就会漂移。

## 2. 现有设计的缺口

现有卷纲五格（位置 / 目标与阻力 / 情绪曲线 / 卷末状态 / 本卷的序列）方向是对的，问题不在“格太少”，在于**每一格只写了意图，没写可执行的契约**：

| 缺口 | 后果 |
|---|---|
| 没有“本卷的独立问题” | 卷末高潮不知道在回答什么，容易变成“打赢了” |
| 没有“入口状态” | 每卷都像重置；上一卷的结果不产生下一卷的问题 |
| 没有“卷末选择” | 高潮只是战斗胜负，不是主角做出的有代价的选择 |
| 没有“旧债/新债/禁揭” | 该还的没还、该埋的没埋、底牌提前揭穿 |
| 序列只有功能散文，没有入口/出口/转折 | AI 写出一段“相关但状态没变”的文字，读起来还像那么回事 |
| 没有线程和承诺的挂载 | 支线消失、承诺遗忘、每个序列都只推进一条线 |
| 没有知识边界 | 角色说出他不该知道的事，悬疑/误会瞬间失效 |
| 没有卷末结算 | 下一卷从旧计划开始，而不是从实际结果开始 |

## 3. 设计原则

1. **每一层先答“必须发生什么变化”，再谈“发生什么事”。** 事件是自由的，状态转移是契约。
2. **一卷一结算：旧债、新债、禁揭。** 卷末不是“爆发 + 断档”，是“结算 + 换挡”。
3. **序列必须有独立的收束。** 它不是卷的切片，是一个能单独成立的迷你故事；否则只是场景群。
4. **承诺账分两层：design 记计划，state 记事实。** 不把同一份台账抄两遍；冲突时 state 是“发生了什么”的权威，design 通过用户拍板修正。
5. **知识边界和不可逆决定要写进契约。** 它们是悬疑、反讽和“卷末不泄气”的结构基础。
6. **模板是诊断问题，不是填写配额。** 只问“这一卷缺了什么功能”，不要求“每卷必须有 8 段/15 拍”。

## 4. 卷纲：推荐六格

**推荐六格**：位置 / 目标与阻力 / 承诺 / 节奏与情绪 / 卷末状态 / 本卷的序列。把每一格从“描述”改成“契约”。下面的文字可直接落进 `design_spec.ts` 的 `write / avoid / form`。

**五格折法**：如果这一轮不想动结构，就把“本卷的承诺”整段折进“本卷在全局的位置”，并把“情绪曲线”保持原名。这样能落地，但承诺账会失去一个可单独 `read` / `edit` 的位置——规划者要一次读完“位置 + 三笔债”，容易只看见位置。

### 4.1 本卷在全局的位置

```ts
{
  heading: "本卷在全局的位置",
  write:
    "本卷的独立故事问题（一句话：谁想要什么、谁挡着、失败会失去什么）" +
    " + 承接（上一卷结束时主角在力量/身份/关系/认知/资源/地理上处于什么状态；只写与上一卷出口的差异和未决项，完整状态从 state/ 现算）" +
    " + 为什么是现在（触发必须从上一卷结果或本卷新舞台里长出来，不是作者需要换地图了）" +
    " + 主线增量（本卷结束时主角对全书核心问题的答案从什么变成什么；删掉本卷，主线几乎不变就是注水）。",
  avoid:
    "具体场次、谁在第几章出场；复述上一卷剧情；把整本伏笔台账抄进来（细节在 state/foreshadowing.md）；写“本卷很精彩”这类评价。",
  form:
    "先一句独立问题，再分“承接 / 为什么是现在 / 主线增量”几行；每条一行，能当约束用。",
}
```

**判据**：

- 独立问题必须能脱离全书单独成立，不是“下一段的过渡”。
- “承接”只写差异/未决项，不复制上一卷的卷末状态。
- “为什么是现在”不能是“作者需要换地图了”；新舞台、新对手、新目标必须从上一卷的结果里长出来。

### 4.2 本卷目标与阻力

```ts
{
  heading: "本卷目标与阻力",
  write:
    "主角想要（外部目标，具体到可失败）" +
    " + 主角需要（主题要求他学会/放下的东西；没想好写（待定））" +
    " + 阻力类型与具体化身（个人/制度/关系网络/世界规则/自身缺陷；混合型写明本卷的具体化身，不要只填一个反派名字）" +
    " + 对手想要什么、凭什么挡着、他的资源与反扑（对手不是等着被打脸的功能件）" +
    " + 升级轴（本卷主要在哪一轴上升级：力量/权力/地理/认知/亲密关系/资源）" +
    " + 失败代价（输了会失去什么人/身份/资源/信念）" +
    " + 难度增量（比上一卷难在哪：旧办法失效、代价更高、对手更聪明，不只是“更强”）" +
    " + 本卷上限（本卷能击败/拿到什么，不能碰什么；战力、资源、规则的天花板）。",
  avoid:
    "具体场次、谁在第几章出场；主角会怎么做（那是序列的事）；只写“敌人更强”；把“想要”写成剧情目标以外的东西。",
  form:
    "主角想要/需要、阻力类型、对手、升级轴、失败代价、难度增量、本卷上限，各一行；能当约束用。",
}
```

**判据**：

- “想要”和“需要”最好在本卷发生一次错位或碰撞；不要求每卷都完成人物弧，但不能完全没有。
- **阻力类型不是分类考试**：允许混合，但必须写本卷的具体化身。《知否》的阻力是嫡庶礼法/家族网络，不是单一反派；《哈利·波特》的可见反派常是红鲱鱼，真正的升级是保护者逐个失去。只写一个人名，AI 会把整卷写成围绕这个人打脸。
- **升级轴决定这一卷“难在哪”**：力量/权力/地理/认知/亲密关系/资源。不要每卷都只升力量；《庆余年》升的是权力位置，《知否》升的是身份/关系阶段。
- 对手必须有独立目标、资源和反扑；否则冲突会退化成事件堆。
- “本卷上限”是防战力崩坏的关键；用相对关系写（能击败谁、不能碰谁），不写精确数值。

### 4.3 本卷的承诺

```ts
{
  heading: "本卷的承诺",
  write:
    "旧债：本卷必须兑现/推进/延期的旧承诺，各兑现到什么程度（只写条目与程度，精确回收位置留给序列/章）" +
    " + 新债：本卷新开的承诺，预计何时还（本卷内 / 下一卷 / 更后）" +
    " + 禁揭：本卷绝不能揭的底牌，3–5 条（哪条真相、身份、关系或能力不能提前出现）" +
    " + 类型义务（可选）：这本书的类型向读者承诺了哪些必须兑现的场景（爱情的分手/确认、惊悚的正面遭遇、成长的幻灭），本卷负责哪几个。",
  avoid:
    "完整的伏笔台账；每一根的精确回收章；每一章的提醒方式（这些属于 state/foreshadowing.md 与序列/章规划）；只写“有伏笔”而不写承诺什么、何时还。",
  form:
    "分“旧债 / 新债 / 禁揭 / 类型义务”四组；每条一行，用名字引用，不引入 ID。",
}
```

**判据**：

- 本卷至少结清一条旧承诺、开立一条新承诺；长线承诺不超过 3 条。
- **《哈利·波特》是样板**：每本解决一个学年谜题，同时推进魂器/预言——单卷独立成立，系列长线每次只推进一点。AI 最容易犯的两个反向错误是“一次揭完，后面没牌”和“只开不收，读者失去耐心”。
- 只登记**跨卷承诺**；本卷内的小伏笔归序列，不要全塞进卷纲。
- “禁揭”是硬约束：序列和章规划都不能提前解决它。
- 类型义务是类型契约，不是通用清单；没有明确类型契约就不写。
- 承诺账是**计划**，不是 canon；实际状态在 `state/foreshadowing.md`，见 §9。

### 4.4 本卷的节奏与情绪

> 这一格现在实际管“节奏”，不只是情绪。若不想改名，可以继续叫“本卷的情绪曲线”；但标题会略窄于内容，测试与文档也要相应保留旧串。

```ts
{
  heading: "本卷的节奏与情绪",
  write:
    "主情绪（这一卷读者主要体验什么：爽/甜/虐/怕/燃/悬）" +
    " + 爽点轮换（本卷用哪几种：打脸/获得/被认可/情绪释放/智谋/认知/守护；各落在哪个序列；同类不连续三次）" +
    " + 2–3 个中高潮的功能与大致位置（用卷内百分比或序列，不写章号）" +
    " + 中点转折（目标变质/代价显形/盟友背叛/身份暴露）" +
    " + 最低谷（失去什么；不能连续高压）" +
    " + 卷末大高潮（类型与必须兑现的承诺）" +
    " + 喘息（哪里留喘息；纯舒缓不超过一章）" +
    " + 卷首钩子（卷首 1–3 章要建立的“为什么现在读”与新期待）。",
  avoid:
    "“高潮迭起”“爽点密集”这类评价词；写死章号；把每个序列都写成大高潮；用爽点替代转折；把情绪曲线写成读者感受的散文。",
  form:
    "按卷首→中段→卷末的条目式；每条写功能与大致位置（百分比或序列），不写章号。",
}
```

**判据**：

- 爽点类型要轮换；纯打脸堆叠会边际递减。经验节奏：每 3–5 章一个小回报，每 10–20 章一个中高潮，每卷一个卷末大高潮——按平台和题材调整，不是配额。
- 高潮前必须有低谷；连续高压会让读者疲劳。
- 卷首 1–3 章要重新建立“为什么现在读”，不能假设读者记得上一卷。
- 卷末最后 1–2 章是“结算 + 换挡”，不是纯总结；纯日常不超过一章。

### 4.5 卷末状态

```ts
{
  heading: "卷末状态",
  write:
    "六轴状态：力量/身份/关系/认知/资源/地理，从卷首到卷末各变成什么；至少一轴不可逆" +
    " + 知识边界（卷末读者知道什么、角色知道什么、谁仍不知道什么）" +
    " + 卷末选择（卷末高潮把主角逼到哪两个都有代价的选项前，他实际选了哪个、付出了什么；不是选择型的高潮写清为什么不需要选择）" +
    " + 代价/负债（失去了谁、欠了什么、被谁盯上；胜利也要有代价，不能只写“赢了”）" +
    " + 旧债结清（用名字指回“本卷的承诺”：哪条已还、哪条推进到一半、哪条延期；没兑现的为什么、何时还）" +
    " + 新债（用名字指回“本卷的承诺”：哪条新承诺已开、预计何时还；新问题如何从本卷结果长出来）" +
    " + 下一卷的问题（不是“突然出现更强的敌人”）" +
    " + 刻意不变的（哪些关系/身份/谜团本卷有意不动，留给后面）。",
  avoid:
    "事件（“主角打败了 X”）；只写“赢了/输了”；写悬念怎么解；把状态写成流水账；重抄整份承诺清单（这里只写结果，清单在“本卷的承诺”）。",
  form:
    "“从…变成…”的状态断言，按六轴列；知识边界/卷末选择/旧债/新债/下一卷问题/刻意不变各一行。",
}
```

**判据**：

- **写状态，不写事件**：事件可以换，状态必须保住。这是改纲的正确姿势。
- 至少一轴不可逆；如果六轴都没变，这一卷只是一个大序列。
- 卷末选择是“两个都有代价的选项里选一个”，不是“打赢了/打输了”。如果没有选择，说明本卷高潮还不是人物的高潮。
- **卷末变化很少是单纯的胜利**：七部案例里只有一部接近纯胜利，且也以重要人物的死和警告为代价。AI 最容易写“打败反派，大家高兴”，这是与样本最大的偏差。
- 知识边界是悬疑、误会和戏剧反讽的结构基础；写清“读者知道什么、角色知道什么、谁仍不知道什么”。
- 新问题必须从本卷结果里长出来，不能天降。
- “刻意不变”防止 AI 为了“每卷都有大变化”而把所有牌一次打完。

### 4.6 本卷的序列

```ts
{
  heading: "本卷的序列",
  write:
    "大致 3–6 个序列（经验区间，不是硬性；超过 8 个先想是不是该拆卷，少于 3 个先想每个序列是否撑得起完整弧）。" +
    "每个序列一行：s<序号> [功能标签]：功能（不是事件）——本序列自己的问题；不可逆转折（从什么变成什么）；主要线程（全书主线/本卷目标/关系或支线）；兑现或埋下哪条承诺；预估体量（范围，不写章数）。" +
    "功能标签可用（不是穷举）：招募/训练/规则揭示/关系转折/代价支付/假胜利/真高潮/收束/换地图/身份暴露；每段最多两个，标签只做诊断，真正要写的是出口状态。 " +
    "最后写因果链：s1 的结果如何导致 s2 的问题；哪个序列负责卷末高潮、哪个负责喘息/关系；本卷从哪个序列进入下一卷的新问题。",
  avoid:
    "展开每段细节（写到那个序列再展开，各自一个文件）；写章号；把序列写成事件清单；每个序列都写“主角遇到…”；把新角色的名字写死（写功能，名字由用户拍板）；把功能标签当分类考试。",
  form:
    "一段一行；最后一行写因果链与卷末高潮落在哪个序列；体量给范围。",
}
```

**判据**：

- 序列的边界由“不可逆转折 + 出口状态不同”定义，不由字数定义。两个序列出口状态相同，它们其实是同一个序列。
- 序列之间是因果链，不是并列的 episode：上一段的出口必须制造下一段的问题。
- 不要一次把 3–6 个序列都展开成详细文件。卷纲只给功能与因果链；写到哪个序列，再展开哪个序列。这也是 AI 动态分层规划更稳的原因：过早细化会锁死工作流。
- 序列行不写新角色名字；需要人时写功能（“一个懂机关的老人”），名字由用户在拍板时给。

**可选：群像/多 POV 变体。** 默认不启用；只有当 POV 线 ≥3 且各线有独立目标时才用。卷末状态按线并列（每条线一行：本卷目标、阻力、卷末状态、与其他线的交叉点），不强行合成一个“主角状态”；序列仍按主线推进，但每个序列标明主视角线，不要让 AI 在每个序列里切所有 POV。单主角/双线作品保持六格原样。

## 5. 序列纲：散文 + 七字段轻契约

### 5.1 为什么仍然不分 `##` 小节

- `list` 里序列纲只占一行 + 首句；一旦有了 `##`，目录会铺小节标题，反而看不出“这是哪一段”。
- `proposal` 对 `sections: []` 的整篇散文按“整篇一格”审阅，用户看到的就是全文；改成表格不会让审阅更安全。
- 一个序列本来就该一口气说完；分小节容易把事件钉死。

所以：**保持 `sections: []`，但要求开头用行首标签写出契约块。** 不是表格，也不加标题。

### 5.2 契约块（写在开头，不必加标题）

```
功能：这个序列在卷里承担什么；推进哪条线程（全书主线/本卷目标/关系或支线）；兑现或埋下哪条承诺。
问题：这一小段谁想要什么、谁挡着、失败会失去什么。它必须能脱离整卷单独成立。
入口 → 出口：入口只写本序列相关的关键前提（处境、资源、关系、谁知道什么、什么威胁悬着）；
           出口写结束时什么是真的，以及这个结果如何导致下一个序列的问题。出口必须与入口不同。
不可逆转折：至少一个；中长序列给 2–4 个。每个写“从什么变成什么”（行动/认知/关系/处境/力量/身份）
           + 谁做了选择 + 代价是什么。没有转折的序列只是场景堆。
承诺：兑现哪条旧承诺、埋下哪条新承诺、什么不能提前揭。
写法约束：哪几处不能写坏（人物要立住、节奏要压住、哪里别太顺）；世界规则/战力上限；哪些事件可以换。
体量：预估字数范围，不写章数。
```

然后写“大致怎么走”：松散的事件线。写到哪一场具体怎么演，留给写手。

### 5.3 七个字段的职责

| 字段 | 它防止什么 | 它不约束什么 |
|---|---|---|
| **功能** | 序列与卷脱节、为写而写 | 具体事件、谁出场 |
| **问题** | 序列变成事件流水账 | 问题怎么解决 |
| **入口 → 出口** | 状态没变、下一段接不上 | 通过什么事件到达出口 |
| **不可逆转折** | “然后……然后……”、可逆的假危机 | 转折发生在第几章、用什么方式 |
| **承诺** | 挖坑不填、提前揭底 | 在哪一章兑现 |
| **写法约束** | 人物写崩、战力崩坏、节奏塌陷 | 具体场景调度 |
| **体量** | 无限膨胀或过度压缩 | 章数、精确字数 |

### 5.4 事件仍然自由

契约只约束“进内城后谁知道什么、失去了什么”，不约束“通过谁进去”。

- 可以换事件、换场景、换对话、加新人物（走现有“先立人再写”的规则），只要出口谓词、转折功能、承诺状态成立。
- 可以“超额”完成一个转折（更有力的版本），但不能跳过出口谓词。
- 如果写作中发现更好的走法，**先改契约，再写正文**；不能让正文静默推翻契约。改契约走 `propose-design`，用户拍板。

### 5.5 不要写进序列纲

- 具体台词、场景调度、章号。
- 抄核心层/世界观/人物卡里已有的设定——引用，别复制。
- 评价词（“精彩”“有张力”）。
- 精确战力数值、精确回收章、新角色的名字。
- “必含 A、B、C”的清单。清单把事件钉死，而事件随时可以换、只有功能稳定。

## 6. 卷型：三种骨架，放 guide 不放字段

三种常见骨架，按核心卖点选；混合是常态，不要强迫一本书只用一种。

| 骨架 | 一句话 | 适用 | 卷末必达 |
|---|---|---|---|
| **A 目标—阻力—升级型** | 主角在期限/门槛前拿到什么，谁挡着，失败失去什么 | 玄幻、仙侠、都市异能、系统、竞技、复仇 | 力量/资源上台阶，身份变化，旧敌结算但留更大幕后，旧债+新债 |
| **B 地图—副本型** | 这群人要通关什么舞台，舞台的规则真相是什么 | 无限流、副本、悬疑、诸天、游戏 | 规则/真相揭一层，主线碎片 +1，关系变化，收益影响现实，带走旧资产 |
| **C 关系—阶段型** | 这一阶段关系或地位要跨过哪道门槛，代价是什么 | 女频古言、现言、宅斗、宫斗、职场、群像 | 关系阶段前进一步，女主有主动选择/可见成长，事业线至少推进一格，新威胁出现 |

**为什么不做成字段**：卷型是创作启发，不是契约。做成 `type: A|B|C` 的字段，模型会为了“选对类型”而套模板，而实际作品常常是 A+B、B+C 混合（《诡秘之主》= 地图 + 序列 + 真相层；《大奉打更人》= 案件 + 势力 + 主线；《庆余年》= 地理 + 权力阶段）。把三种骨架写进卷纲规范的 `guide`，让模型按需参考即可。

## 7. 章规划接口：从序列契约投影

章规划（`.talemate/plans/ch_<N>.md`）是执行工件，不是作品文档。它应该拿到：

- **当前序列契约的切片**：这一章要兑现哪个转折、目标出口增量是什么。
- **卷契约的相关切片**：本卷独立问题、旧债/新债、禁揭、本卷上限。
- **入口快照**：与本章相关的状态事实（不是全部）、POV 人物知识、地点/时间、到期承诺。
- **2–5 个 scene beat**：目标/阻力/转折/代价；以及“放大点/半句带过”（现有设计已有）。
- **在场人物 + 声音卡 + 他们想要什么/知道什么/隐藏什么**。
- **连续性约束**：必须埋/收/提的承诺；不能违反的知识边界；读者已知 vs 角色已知。
- **本章预期出口增量**：给章末状态回写一个目标，避免“写完再想发生了什么”。

### 7.1 章规划新增四个字段

在现有“意图 / 产物（按序） / 每一步要什么”的结构里，加四项：

```
对应序列与功能：这一章推进哪个序列的哪一项契约（问题/转折/承诺）。
本章的价值变化：从什么变成什么（信息/关系/资源/位置/认知）。
本章不能提前兑现：哪些问题必须留着，哪些禁揭项不能碰。
章末的读者问题：这一章结束时读者在等什么（动作中断/发现/关系变化/新问题）；
                如果是喘息或收束章，余味即可，不必强行断章。
```

**判据**：

- 每一章至少改变一项：信息、关系、资源、位置、认知。什么都不改变的一章是填充，应该合并或删掉。
- “本章的价值变化”不是“发生了什么事”，而是“读者/人物对世界的状态认知变了什么”。
- 章末钩子必须与主线强相关，不能为钩而钩；不要每章都制造假 cliffhanger。
- 章规划不能让人物使用他不该知道的信息；这是悬疑和误会的结构基础。

### 7.2 规划者要读卷纲

`planner.system.txt` 现在只说读“覆盖这一章的序列纲”。应补一句：**也读卷纲的“本卷在全局的位置”“本卷目标与阻力”“本卷的承诺”“本卷的节奏与情绪”**——独立问题、旧债/新债、禁揭、对手计划、本卷上限、这一章在卷内节奏中的位置。序列契约说“这一段必须让什么为真”，章是它的一个投影。

### 7.3 正文不能静默推翻契约

如果执行中发现更好的走法，改变了序列的出口状态或承诺，应该停下来，走 `propose-design` 改序列纲，用户拍板后再写。不能让正文静默推翻契约——那会让后续序列的入口对不上，而用户看不到这个断裂。

## 8. 卷末结算与下一卷

一卷写完（或用户说“这一卷结束了”）时，先结算，再写下一卷。**不新增工具，不新增文档类型**；这是一次对话 + `propose-design`。

1. **对账**：读“卷末状态”与 `state/` 的实际状态；逐项看六轴变化、知识边界、旧债结清、新债开立、独立问题是否回答。
2. **报告**：把差异摆给用户：哪些按计划发生了、哪些没发生、哪些是写作中长出来的新东西。不要静默修正。
3. **裁决**：用户决定——补一段把卷末写完、修改卷末状态、还是把差异带进下一卷。改卷纲走 `propose-design`。
4. **下一卷**：用**实际卷末状态** + `state/foreshadowing.md` 现算下一卷的入口、旧债、新债、禁揭；不缓存“全书分卷表”。
5. **不评分**：结算只回答“状态是否不可逆、旧债是否结清、新债是否开立、钩子是否从结果长出”，不回答“这一卷好不好”。质量由用户拍板，不做评审 agent。

**卷间衔接**：先铺垫下一卷，再引爆上一卷。卷末高潮前就应该出现下一卷的线索/敌人/地图；卷末不是“大高潮后写三四章日常”，而是“结算 + 换挡”。纯舒缓不超过一章。

## 9. 承诺账：design 与 state 的分工

| 位置 | 记什么 | 什么时候写 |
|---|---|---|
| **卷纲“本卷在全局的位置”** | 旧债（必须兑现/推进/延期，兑现到什么程度）、新债（本卷开立，预计何时还）、禁揭（3–5 条） | 规划这一卷时 |
| **序列纲“承诺”字段** | 本序列兑现哪条旧承诺、埋下哪条新承诺、什么不能提前揭 | 展开这个序列时 |
| **`state/foreshadowing.md`** | 实际状态：埋设位置、计划回收窗口、状态（已埋/已暗示/已回收/超期/放弃）、正文证据 | 每章写完后 |

**规则**：

- **不引入 ID**。用名字引用，符合仓库“不做条目级 ID 引用”的约定。
- **计划不是 canon**。卷纲/序列纲里的“打算在第 N 章揭晓”只存在于计划里，不能写进 `state/` 当作已经发生；检索时也要过滤未来事件。
- **state 是“发生了什么”的权威**；design 通过 `propose-design` 修正，不静默覆盖。
- **逾期处理**：超期的承诺只有两种处理——接下来几章内让它重新露面并给新信息，或者由用户拍板放弃并写明原因。最忌讳装作没埋过。
- **长线承诺不超过 3 条**；每条跨卷承诺在最终回收前，至少要有一次“近期激活”。

**知识边界**放在卷末状态、序列出口和角色状态文件里，不新增根、不做 schema。每条回答：谁知道什么、谁不知道什么、谁误以为什么。

## 11. 明确不做

| 不做 | 为什么 |
|---|---|
| **整本大纲** | 能算出来的不要存；存下来一定会被写作推翻，脱节的缓存比没有更糟。 |
| **章数/字数配额** | 章数是写出来的结果；用字数反推结构会注水或仓促。只给经验区间，不锁死。 |
| **15 beats / 每卷 8 序列** | 这是全书/电影的经验值；每卷都套会让读者学会节奏，稀释真正的全局高潮。 |
| **每卷都“全盘皆输”** | 反转会贬值；卷末可以是局部胜利/失败 + 新问题。 |
| **事件清单** | 清单把事件钉死，AI 会填表；契约只约束状态转移和转折功能。 |
| **质量打分 / 评审 agent** | 产品明确否决“让另一个 agent 审查 agent 产出”；拍板永远是人。 |
| **自动改稿 / 自动回写企划** | 冲突报给用户裁决；改动走 propose-design + 用户拍板。 |
| **条目级 ID 引用** | 仓库约定不做；用名字引用。 |
| **把未来计划写进 state** | 计划中的未来事件不是 canon；模型会把它当成已经发生。 |
