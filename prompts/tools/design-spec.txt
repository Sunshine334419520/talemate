Return the structural spec for a design document kind: its exact section headings and what belongs in
each — or, for kinds that are plain prose (character cards, sequence outlines), the writing method
instead. Every other tool addresses sections by name (read-design, propose-design, the status card) —
inventing your own headings breaks them.

Call this whenever the conversation is about **designing the novel** — the user telling you what
they want to write, or asking to work on a layer. A story-idea discussion usually touches 核心设定
and 世界观; a design pass usually touches one layer. Call it once per layer in play.

Do NOT call it for anything else: writing a chapter, asking about status, or anything that isn't
about designing the story.

Draft from the user's own words, not by interrogating field by field, then propose it with
propose-design — the user reads the draft before anything is written to a file.

layer: core | world | characters | outline — a layer that holds several kinds of document returns
all of them (outline → 卷纲 and 序列纲).
name: one path under design/ whose kind has its own spec — outline/vol_<N>.md,
outline/vol_<N>/s<M>.md. Give layer or name, not both. Documents with no spec (topic pages, chapter
plans) are written free-form.
