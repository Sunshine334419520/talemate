# 知识点 14 · 判据的强度阶梯 L1–L6

> **职责**：把手册 §3.2 讲透——六级判据各自能回答什么、不能回答什么、偏差从哪来；以及为什么「强」不是「更高级」，而是「更接近真实价值，也更贵、更有偏」。
> **读者**：已经知道「好」有四个维度，接下来要选证据的我。
> **对齐代码**：不涉及代码 · 对齐手册 §3.2 / §3.3 / §4.6（2026-10-30 版）

---

## 一分钟版

> L1 结构、L2 行为、L3 启发式、L4 judge、L5 盲测、L6 用户信号。  
> 越往下越接近「真实价值」，也越贵、越主观、越有偏。  
> **L1+L2 必须覆盖 100% 的 case**；L3 只做仪表；L4 做日常回归；L5 做关键决策；L6 做长期校准。  
> 不要问「哪一级最好」，要问「这个问题该用哪一级证据」。

> 手册标题写「五种判据」，但表里实际是 L1–L6 六级；这里以表为准。

---

## 1. 「强度」到底指什么

不是「越强越正确」，而是：

| 越往上（L1/L2） | 越往下（L5/L6） |
|---|---|
| 便宜、快、客观 | 贵、慢、主观 |
| 只能测表层/契约 | 能测真实价值 |
| 偏差小但视野窄 | 视野宽但偏差大 |
| 适合全量回归 | 适合关键决策/长期校准 |

所以「L6 比 L1 强」是错的。  
正确说法是：**L1 回答「有没有资格被测量」，L6 回答「用户到底买不买账」。**

---

## 2. 六级判据

| 级别 | 判据 | 能回答 | 不能回答 | 偏差来源 | 单次成本 |
|---|---|---|---|---|---|
| L1 | 结构/契约断言 | 格式合法吗、字段全吗、引用的工具存在吗 | 内容好不好 | 几乎无 | ~0 |
| L2 | 行为断言 | 该调的调了吗、该写盘写了吗、有没有越权 | 措辞好不好 | 断言写错 | ~0 |
| L3 | 规则化启发式 | 长度、句长分布、禁用词、重复率 | 语义质量 | 指标选偏 | ~0 |
| L4 | LLM-as-judge + rubric | 覆盖度、风格、逻辑一致性 | 读者会不会追 | judge 自身偏好 | ¥0.01–0.1 |
| L5 | 成对盲测（pairwise） | A 和 B 哪个更好 | 好多少 | 顺序偏差、评委疲劳 | 人 5–15 min |
| L6 | 真实用户信号 | 用户接受/拒绝/修改吗 | 为什么 | 幸存者偏差、样本自选 | 免费但慢 |

---

## 3. L1：结构/契约断言

### 3.1 它问什么

> 输出的形状对不对？引用的东西存在吗？

例子：

- 文件存在吗？
- JSON 能 parse 吗？
- 必填字段全吗？
- prompt 里提到的工具 id，在 `BUILTIN_TOOLS` 里存在吗？
- 不该出现的文本出现了吗？

### 3.2 它不测什么

不测「内容好不好」。  
一段格式完美、工具 id 全对、JSON 合法的输出，完全可能是废话。

### 3.3 为什么它是地基

如果 L1 挂了，后面的 L4/L5 打分是噪声：

- 输出格式不合法，judge 读不懂；
- 工具 id 不存在，行为断言无从谈起；
- 文件没写，L2 的「写了什么」也测不了。

所以实践配比是：**L1 + L2 覆盖 100% 的 case，必须全过。**

### 3.4 talemate 例子

最高价值的一条 L1：

```text
prompts/tools/<id>.txt 与 BUILTIN_TOOLS 是 1:1
```

写错一个 id，模型就会去调一个不存在的工具。  
这是纯静态检查，零成本，但能挡住一类「看起来在跑、其实没这个工具」的故障。

---

## 4. L2：行为断言

### 4.1 它问什么

> 世界状态变了吗？该调的调了吗？有没有越权？

不看输出文本，看：

- 工具调用序列；
- 参数里的路径；
- 文件系统快照；
- 是否交回用户；
- 是否越权写盘。

### 4.2 反向断言更重要

正向断言：

```text
toolCalled("read")
```

反向断言：

```text
toolNeverCalled("write", "draft 模式不该落盘")
noWriteUnder("characters/", "用户没确认前不该写角色")
turnEndedWithoutProposal()
```

模型的默认失败模式常常是**过度作为**：多调、多写、多问。  
反向断言比正向断言更能抓这个。

### 4.3 talemate 例子

`probe` 判 `advanced` / `stopped` 不看正文——正文里「列菜单」和「替你决定」都含「角色」二字，关键词分不开。  
它只看：

```text
有没有对 characters/ 目录动手
```

这是 L2 的硬证据：**世界状态变化**，不是模型自述。

---

## 5. L3：规则化启发式

### 5.1 它问什么

> 长度、句长分布、禁用词、重复率、对话比例……这些廉价统计量有没有异常？

例子：

```ts
const stats = {
  avgSentenceLen: mean(sentences.map(s => s.length)),
  longSentenceRatio: sentences.filter(s => s.length >= 40).length / sentences.length,
  causalConnectives: (text.match(/因为|所以|于是|结果|没想到|原来/g) ?? []).length,
  dialogueRatio: dialogueChars / totalChars,
};
```

### 5.2 为什么只能当仪表

L3 极易被优化：

> 告诉模型「多用连接词」，连接词数量立刻上去，故事质量不动。

所以 L3 只能做：

- 监控；
- 异常告警；
- 回归时的辅助信号。

**不能单独作为验收标准。**  
这条纪律叫「可优化指标不能单独作为验收标准」。

### 5.3 什么时候可以信

当 L3 指标**同时**有 L4/L5 证据支持时。  
比如句长变长、同时 L5 盲测也偏向新版，才能说「叙述节奏变好」，而不是「句长指标变好」。

---

## 6. L4：LLM-as-judge + rubric

### 6.1 它问什么

> 覆盖度、风格、逻辑一致性这些「不能靠关键词」的维度，模型能不能按 rubric 判？

### 6.2 三个设计决定

**(a) 判据可判定，且带锚点**

不要写「写得好不好」，写：

```text
维度：讲述感（1–5）
1 = 像镜头在切、像提纲在推进
3 = 有前因后果，但叙述者时有时无
5 = 像有人在讲故事：有前因后果，有叙述者的判断和态度

只输出 JSON：
{"score": 1-5, "evidence": "原文里支持这个分数的一句", "reason": "≤30字"}
```

`evidence` 是关键：要求 judge 引用原文，能挡掉一半幻觉打分，也方便复核。

**(b) 用不同的模型/不同的 prompt 判断**

执行和评判是两种能力。judge 可以用更小更便宜的模型；而且小模型往往更严格。  
同族模型互相包庇，是已知偏差。

**(c) judge 必须被校准**

见 §4.6：人工金标、加权 κ、冻结校准集。  
κ 低通常是 **rubric 的问题**，不是 judge 的问题——判据含糊，人和模型都会飘。

### 6.3 它不能回答什么

- 读者会不会追更；
- 这个改动值不值得上线；
- 真实用户愿不愿意为它付费。

judge 是「有 rubric 的读者代理」，不是用户。

---

## 7. L5：成对盲测

### 7.1 它问什么

> 同一 case，A 和 B 哪个更好？

### 7.2 设计要点

- **盲**：隐去版本号，只给 A/B；
- **随机左右**：每对随机交换，防止顺序偏差；
- **允许平局**；
- **只看胜负/平，不看分数**；
- **统计用符号检验**。

talemate 的 `style-bench` 已经实现：

```text
blind/<case>/A.md
blind/<case>/B.md
key.json
```

先读 blind，再看 key。

### 7.3 它不能回答什么

- 好多少；
- 为什么好；
- 能不能规模化。

所以 L5 适合**关键决策**（改主线 prompt、换模型），不适合每次提交。

---

## 8. L6：真实用户信号

### 8.1 它问什么

> 用户接受、拒绝、还是修改？

talemate 有一个别人没有的信号：**主编否决率**。

口径必须写清：

```text
分母 = 被拍板的提案数
不是 = 生成的提案数
```

为什么？  
如果用生成数作分母，会漏掉「模型自己放弃了、根本没交到用户面前」的那部分；那个数字会虚高。

### 8.2 它不能回答什么

- 为什么拒绝；
- 拒绝是内容问题还是 UI 问题；
- 样本自选带来的偏差。

### 8.3 偏差

- **幸存者偏差**：只统计还留下来的用户；
- **样本自选**：愿意拍板的人，可能本来就更耐心；
- **慢**：要等真实使用，不能当天出结论。

所以 L6 适合**长期校准**，不是日常回归。

---

## 9. 实践配比：不要只用一级

| 场景 | 用什么 |
|---|---|
| 每次提交 | L1 + L2 全量；L3 监控 |
| 日常 prompt 回归 | L4（已校准）＋ L1/L2 |
| 改主线 prompt / 换模型 | L4 + L5，必要时 L6 |
| 关键产品决策 | L5 + L6 + 成本护栏 |
| 线上异常 | trace（观测）→ 抽 case → L1/L2/L4 |

手册的配比：

- **L1+L2 覆盖 100% case**；
- **L3 廉价监控**；
- **L4 日常回归**；
- **L5 关键决策**；
- **L6 长期校准**。

---

## 10. 六级和四个维度的关系

| 维度 | 主要靠哪些级别 |
|---|---|
| 能力上限 | L4 / L5 / L6 |
| 可靠性 | L1 / L2 / 重复的 L4 |
| 经济性 | L3 + 成本/延迟指标 |
| 可维护性 | 静态审查 + 载体归属（不是某一级判据） |

注意：**没有一级能单独覆盖四个维度。**  
L1/L2 保证「可测」，L4/L5/L6 才回答「好不好」。

---

## 11. 常见误解

| 误解 | 为什么错 |
|---|---|
| 「L1 过了，质量就没问题」 | L1 只保证格式/契约，不测内容 |
| 「L2 行为对，文笔就对」 | 行为对只说明没越权/没漏调，不说明写得好 |
| 「L3 指标涨了，就是变好」 | L3 极易被优化，只能当仪表 |
| 「L4 是自动 judge，所以客观」 | judge 有偏好，必须校准；rubric 含糊时 κ 会很低 |
| 「L5 比 L4 高级，所以都用 L5」 | L5 贵、慢、样本小；日常回归用不起 |
| 「L6 是真实用户，所以最准」 | 有幸存者偏差、样本自选、分母口径问题 |
| 「六级是成熟度阶梯，越高越好」 | 不同问题需要不同证据；L1/L2 是地基，不是低级 |

## 12. 自检

1. 一段输出：JSON 合法、工具 id 全存在、`write` 调用路径正确，但正文像流水账。  
   它过了哪几级？能说「质量好吗」吗？
2. 为什么 L3 的「连接词数量」不能单独作为验收标准？举一个模型学会「看起来像」的例子。
3. L4 的 rubric 至少要有哪三样东西？为什么 `evidence` 字段能减少幻觉打分？
4. L5 的盲测设计要防哪两个偏差？统计上为什么用符号检验而不是平均分？
5. L6 的「主编否决率」分母应该是什么？用生成提案数作分母会漏掉什么？
6. 把「L1+L2 覆盖 100%」「L3 仪表」「L4 日常」「L5 关键」「L6 长期」各用一句话解释为什么。
