# 知识点 1 · 为什么普通测试测不了 agent

> **职责**：把手册 §1.1 讲透——普通测试的三根柱子在 agent 上分别怎么塌、塌了之后由什么补位、以及「字符串为什么补不回来」这条最硬的推论。
> **读者**：学到第一个知识点、并且想在往下走之前把地基踩实的我。
> **对齐代码**：不涉及代码 · 对齐手册 §1.1 / §1.2 / §3.3（2026-10-30 版）

---

## 一分钟版

> Agent 的「对」不在一次返回里，而在一条轨迹的分布里。所以：重复跑是为了**估计**分布（不是提高确定性）；字符串不够用，因为 `轨迹 → 文本` 是多对一、不可逆（所以要在**边界**埋 trace）；单元测试替不了它，因为它测的是另一个空间（覆盖率 ≠ 完成率）。

---

## 1. 原文那张表到底在说什么

| 系统类型 | 输入→输出 | 判据 | 工具 |
|---|---|---|---|
| 普通软件 | 确定 | 相等 | 单元测试 |
| ML 模型 | 统计 | 分布 | 离线指标（accuracy/F1） |
| **Agent** | **轨迹**（多步、带工具、带副作用） | **程度性 + 主观 + 多目标** | **eval + trace** |

这张表不是分类学，是**判据的来源**。它回答的问题是：*你凭什么说这次跑对了？*

- 普通软件：`f(3) === 9`。判据来自**规格本身**——输入确定、输出确定，所以「相等」就是全部。
- ML 模型：单张图判不了对错（模型本来就会错 5%），判据从「这一次」上移到「这一批的分布」。
- Agent：连「一批的分布」都不够，因为输出不是字符串，是一条轨迹。

所以这张表真正的意思是：**系统从「确定」走向「轨迹」，判据的载体一级一级往上移**——从「一次调用的返回值」，到「一批调用的统计量」，再到「一次运行的完整事件序列」。工具跟着判据走，不是反过来。

---

## 2. 拆开看：单元测试靠三根柱子，agent 一根都不给

单元测试的可靠，建立在三个假设上。手册列的「三点特殊性」，就是这三根柱子被拆掉的位置。记住这个对应关系，比背三行表有用。

### 柱子 1 · 确定性 —— 被「长尾失败」拆掉

单元测试默认**同输入必同输出**，所以挂了能重跑、能二分、能打断点。

Agent 不是。「同一个 bug 可能一百次里出现三次，而你在 CI 里永远复现不了。」这不是抱怨不稳定，是一个结构性后果：

- 采样本身带随机性（temperature、top-p）；
- 上下文长度、工具返回内容、并发时序都会改变轨迹；
- 失败发生在**多步的组合**上：第 3 步少读一个文件，第 7 步就写歪了，而两步单独看都没错。

于是「复现」从**必然**变成**概率**。你没法说「这个 bug 存在」，只能说「它以 p≈3% 的概率存在」。单元测试的调试闭环——失败 → 复现 → 定位 → 修 → 再跑——在这个概率面前断了。

**这就是 pass@k / pass^k / 噪声地板存在的理由**：它们不是统计学装饰，是在确定性消失之后，唯一还能承载「可复现」的东西——把可复现性从「过程」转移到「分布」上。

### 柱子 2 · 相等判据 —— 被「程度性」拆掉

「这段正文好不好」没有 `==`，只有 rubric 上的位置。

更狠的推论：**判据不是相等时，「通过」这个二值信号的信息量会塌缩**。3 分和 4 分都不算失败，但产品上完全是两回事；而 5 分制对同一批改动的分辨力是 0/1 制的 3–4 倍（对照 §3.4 动作 5 的样本量表：检出 10pp，二值要 ~120 个 case，连续分只要 ~40 个）。

### 柱子 3 · 单一调用 —— 被「轨迹」拆掉

手册：「『写了什么』只是一部分，『怎么走到那里的』同样重要。」

关键在**同样重要**。不是「顺便也想看过程」，而是：**有些正确性根本不在最终字符串里**。

手册的真例子（§3.3 L2）：`probe` 判 `advanced` / `stopped` 时**不看正文**——正文里「列菜单」和「替你决定」**都含「角色」二字**，关键词分不开；它只看「有没有对 `characters/` 目录动手」这条硬证据。

这个例子的三层意思：

1. 输出文本**无法区分**两种行为；
2. 行为差别在**世界状态的变化**里（文件有没有被写）；
3. 而「世界状态」只有把一次运行当成**一条带副作用的时间线**看时才存在。

换句话说：**agent 的「输出」是「它对这个世界的改动 + 它到达改动的方式」。字符串只是这条轨迹的一个投影，而且是丢信息的投影。**

---

## 3. 合起来：判据的单位变了

> 单元测试测的是**一个函数的一次返回**；agent 要测的是**一次运行的整条轨迹**。单位变了，工具、判据、可复现性的定义全都要跟着变。

三根柱子塌掉之后，「测试」裂成两个东西（这就是 §1.2 那张两坐标系的图）：

| 柱子 | 塌了之后 | 补位的东西 |
|---|---|---|
| 确定性 | 失败不可复现 | **trace**：不复现也能看现场 |
| 相等判据 | 好没有 `==` | **rubric / pairwise**：给「位置」而不给「真假」 |
| 单一调用 | 对错不在字符串里 | **行为断言 + trace**：看世界状态和调用序列 |

注意：补位的**不是「更好的单元测试」**，而是两类新仪器——**统计仪器**（eval，答「这批改动整体好不好」）和**观测仪器**（trace，答「这一次为什么坏」）。两个坐标系，不是一个东西的两种精度。

---

## 4. 最容易踩的坑：硬塞

因为「普通测试测不了」，人会想**焊回去**：把最终输出截成字符串，写 `expect(text).toContain("角色")`，`bun test` 绿了，心里踏实了。

代价两条，手册后面都点了名：

1. **断言变成可优化目标**。你断言「含关键词」，模型就学会「看起来像」——§3.5 的「可优化指标」坑，也是 P1「不能判定的『好』不是指标，是意见」。
2. **假绿比红更贵**。测试绿着，真实完成率掉了 9 个点，而没有任何仪器能发现——因为仪器本身坏了。

正确姿势不是「给 agent 写单元测试」，而是**分工**：确定性部分（装配、hash、check 函数本身、prompt 引用的工具 id 是否存在）留给单元测试；概率部分交给 eval + trace。talemate 就是这么分的——`bun test` 管前者，`eval/` 管后者，互不替代。

## 5. 字符串为什么补不回来（本知识点最硬的一块）

> 这是自检第 2 问的完整答案。当时没答上来，所以单独成节。

### 5.1 缺的是什么

缺的不是「更多文本」，而是**过程签名**：这次运行调了哪些工具、什么顺序、什么参数、对世界状态改了什么。concept 上就是**轨迹**（§5.2 展开成三层 span：`invoke_agent` / `chat` / `execute_tool`）。

### 5.2 为什么「不可能」补回来

因为 `f: 轨迹 → 文本` 是**多对一**的。不同轨迹可以投影出同一句话。多对一不可逆——不是「文本还不够长」，是信息在生成那一刻就丢了。

同一个 case，两条完全不同的轨迹：

| | 轨迹 A（越权，该判 advanced） | 轨迹 B（正确，该判 stopped） |
|---|---|---|
| 工具调用 | `read design/core.md` → **`write characters/lin.md`** | `read design/core.md` |
| 世界状态 | `characters/` 多一个文件 | 没变 |
| 输出文本 | 「我已经把林某加进去了，设定如下……」 | 「我给三个候选方向，你想选哪个？」 |

更糟的是，模型完全可能输出「我先不急着写，想跟你确认一下——我倾向于把林某设成……」，而**同一轮里已经写了盘**。这时文本和行为是**矛盾的**，而 probe 要判的正是这个矛盾。拿矛盾的产物去判矛盾，判不出来。

根因一句话：

> **文本是模型对自己行为的叙述，不是行为本身。**

### 5.3 两个加固理由

1. **自述不可信**。在 prompt 里缝一句「请报告你调用了哪些工具」没用——这是让被告当证人。它报告的仍是「它以为它做了什么」，而自述本身也是被采样的。
2. **观测会扰动系统**。为了问清它做了什么而多问一轮，轨迹就被改写了（多一步、上下文变长、可能触发压缩）。你得到的是另一个系统的报告。

### 5.4 唯一可信的 ground truth 在「边界」

都是世界状态，都不经过模型的嘴：

- **工具执行器**：调用序列 + 参数 + 返回值 + 成败；
- **provider**：token 数、耗时、`stop_reason`；
- **文件系统**：运行前后的快照 diff。

推论，也是后面两个大设计的根：**trace 必须在边界记录，不能从对话文本反向重建**。反向重建就是求一个不可逆函数的逆——这是 §4.8 把 replay 做成 provider、§5.4 埋点踩在工具层的全部理由。

## 6. 自检三问（原题 + 我的回答 + 批改）

### 问 1（🟡 前半对）

> 为什么「同一配置跑 10 次」在普通软件里无意义，在 agent 里却是**第一件**要做的事？

我的回答：普通软件确定性，跑 10 次不会变；agent 是一次轨迹，过程和结果都不确定，所以跑 10 次是为了尽可能提高确定性。

批改：前两句满分。结尾反了——**跑 10 次不提高确定性，它估计确定性的边界。**

一个想改系统，一个只想量系统，方向相反。类比：反复量血压不会让血压变好；量血压是为了知道多少波动算正常。手册把它排在第一（P6：**改任何东西之前**先测同一配置重复跑的波动），正因为它是个**量具**，不是**疗法**。

为什么这个区别要命，看 §3.4 的数字：

- 30 个 case、真实成功率 65% → **sd ≈ 8.7 个百分点**；
- 1 个 case 翻转 = 3.3pp；
- 所以 **62% → 71% 很可能只是噪声**（净翻转才 3 个）。

如果以为「跑 10 次让 71% 更可信」，那么你在拿一段噪声当结论。真实情况是：这 10 次测出来的不是「更准的 71%」，而是「量具的精度只有 ±8.7pp」。

准确动词是**估计**（estimate）——用 k 次样本估计通过率这个参数。所以 pass@k / pass^k 都是**估计量**，不是「跑多了就对」。

### 问 2（⬜ 当时答不上来）

> probe 那个例子说明「输出字符串」缺了哪一类信息？为什么这类信息**不可能**从字符串里补回来？

完整答案见上面 §5。记住两条：缺的是**过程签名**；补不回是因为**多对一不可逆**。

### 问 3（🟡 结论对，诊断偏）

> 「我们给 agent 写了 200 个单元测试，覆盖率 80%，所以质量有保障」错在哪根柱子上？

我的回答：这句话是错的；单元测试完全不适用于 agent，应该是柱子 2。

批改：结论对，诊断偏，而且「完全不适用」要收回一半。

**诊断**：柱子 2 只抓到表层（那些断言大概率是 `toContain`）。根层是**柱子 3 + 单位错误**：

> 80% 覆盖率是对**代码空间**的覆盖；完成率是对**轨迹空间**的度量。两个空间之间不存在「覆盖率」这种东西。

`writeDesign()` 可以覆盖到 100%，每行都执行、返回值都断言过；线上照样出现「该交回用户时没交回」——**200 条测试一条都不会红**，因为没有任何一条测试里存在「多步 + 工具 + 副作用」这条轨迹。

**「完全不适用」要收回**：单元测试是必要的，只是**只在其合法量程内有效**。它坏不是因为它是单元测试，是因为有人拿它给一个它测不到的问题作证。talemate 自己就是这么分的：`bun test` 管装配与契约，`eval/` 管质量。

三层拆解，一层比一层深：

| 层 | 错在哪 |
|---|---|
| 表层（柱子 2） | 断言用关键词，把「好」退化成「像」 |
| 中层（柱子 1） | 对随机输出做确定性断言，绿灯本身不稳 |
| **根层（柱子 3 / 单位错误）** | **用「一次调用」的仪器，回答「轨迹分布」的问题** |

记成一句：**覆盖率 80% 是一个关于代码的事实，不是关于质量的事实。** 它证明「这些代码被跑过」，不证明「这些轨迹走对了」。

## 7. 我的误解清单（复习只看这节）

1. **「重复跑是为了提高确定性」** → 错。重复跑是**测量**噪声地板（P6），不是降低噪声。降噪是另一件事（温度、约束、拆步骤）。
2. **「单元测试完全不适用于 agent」** → 错。是**量程**问题：确定性部分归单元测试，概率部分归 eval + trace。错在越界作证，不在使用。
3. **「字符串里没写清楚，多问一句就行」** → 错。问是让被告当证人，且观测会扰动轨迹。ground truth 在边界（工具执行器 / provider / 文件系统）。
4. **「覆盖率能代表质量」** → 错。代码空间 ≠ 轨迹空间，两者之间没有覆盖率可言。

## 8. 与后文的接口

这个知识点是后面所有设计的**根**，三条线从这里长出去：

- **往上（§1.2）**：既然是两个坐标系，就必须**先定事件 schema，再往上长两头**——因为 eval 的原料（trace）和 trace 的产物（case）是同一套事件。
- **往右（§3.2）**：柱子 2 塌了 → 判据要分级（L1–L6）；柱子 1 塌了 → 统计工具箱（§3.4）；柱子 3 塌了 → 行为断言 + 埋点（§5.2）。
- **往下（§7）**：落地顺序 S1-2（trace sink）排在 S1-6（judge）之前，正是「先有事件、才有人判」。
