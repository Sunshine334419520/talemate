# 知识点 3 · 闭环：假设 → 单变量 → 重复 → 配对 → 决策 → 沉淀

> **职责**：把手册 §1.3 的闭环讲成可执行流程——每一步的输入/输出、它依赖哪条第一原则、以及在哪一步最容易把实验做成「跑了一下」。
> **读者**：已经理解「两个坐标系」、准备把 eval 真正用于决策的我。
> **对齐代码**：不涉及代码 · 对齐手册 §1.3 / §2 / §3.4 / §3.6（2026-10-30 版）

---

## 一分钟版

> 闭环不是「跑一遍 eval」，而是：**先写下一个可被推翻的假设 → 只动一个干预并证明它真的发生 → 重复跑固定 case 估计噪声 → 按同一个 case 配对比较 → 用事先定好的规则决策 → 把失败样本、结论和基线沉淀下来。**  
> 没有闭环，数字只是数字；有闭环，数字才能变成「保留 / 回滚 / 再改」的依据。

---

## 1. 为什么「跑一遍 eval」不是闭环

「跑一遍」通常长这样：

```text
改 prompt
  → 跑 30 个 case
  → 看到分数从 62% 到 71%
  → 觉得变好了
```

它缺了四样东西：

1. **假设**：没有说「改什么、为什么、预期哪个指标动」；
2. **单变量证明**：不知道到底是 prompt 改了，还是模型/温度/上下文也变了；
3. **噪声**：不知道 62%→71% 是信号还是 3 个 case 的随机翻转；
4. **决策规则**：阈值是看到数字之后才想的，事后总能找到理由保留。

所以手册把闭环画成六步，每步都在补一个「跑一下」缺掉的判据。

---

## 2. 六步各自在防什么

### 2.1 假设：先写「什么会变、为什么」

坏的假设：

> 加了这条纪律，模型会少绕路。

它不可判定：「绕路」是什么？哪个指标？预期方向？可接受代价？

好的假设：

> 在 draft 模式加「先列候选、不落盘」一条，会让 `characters/` 的未授权写盘从 9/30 个 case 降到 ≤3/30，同时 pass^3 不下降。

它包含四件事：

- **干预**：只加这一条；
- **主指标**：未授权写盘 case 数；
- **护栏**：pass^3 不能下降；
- **可推翻**：如果没降，或 pass^3 掉了，假设失败。

**假设不是愿望，是一个可被数据打脸的预测。**

### 2.2 单变量：只动一个干预，并证明它真的发生

「只改一处」不够。你还得证明：

- 装配后的 prompt **确实变了**；
- 变的是你以为的那个片段；
- 变体没有静默退化成 baseline。

这正是 P4「替换必须被证明发生」：

> 替换串没命中 → 变体静默退化成 baseline → 你得到「没差异」的结论 → 假阴性，且完全无感。

具体做法（talemate 已有雏形）：

```text
before_hash = hash(装配后的 system + tools + mode)
应用替换
after_hash = hash(...)
if (before_hash === after_hash) throw "实验没做成"
```

单变量不是「只能改一个文件」。你可以改一段 prompt 里的三句话，只要它们被当作**一个干预**，且报告里能说清「这次干预是什么」。  
不能同时改 prompt + 温度 + 工具集，然后说「prompt 有效」。

### 2.3 重复：先估计噪声，再谈差异

重复跑不是「让分数更可信」，而是**估计同一配置的波动**（P6）。

手册给的具体数字：

- 30 个 case、真实成功率 65% → `sd ≈ 8.7pp`；
- 1 个 case 翻转 = `3.3pp`；
- 所以 62% → 71%（+9pp，约 3 个翻转）**很可能只是噪声**。

重复要满足：

- 同一 case 集；
- 同一模型、温度、最大输出；
- 同一初始世界 / 同一 HOME；
- 同一代码版本；
- 记录全部 run，包括 error / timeout。

**噪声地板是实验的一部分，不是事后解释。**  
先测 baseline 的波动，再决定「多大的差异才值得看」。

### 2.4 配对：同一个 case 的 A/B，不是两个百分比相减

配对比较的单位是「同一个 case、同一轮」：

| | B 失败 | B 成功 |
|---|---:|---:|
| **A 失败** | 都没过 | **b：A 败 B 成** |
| **A 成功** | **c：A 成 B 败** | 都过 |

只数翻转：

```text
b = A 失败、B 成功的 case 数
c = A 成功、B 失败的 case 数
净翻转 = b - c
```

然后用 McNemar 精确检验。手册表：

| 净翻转 | 双侧 p | 结论 |
|---:|---:|---|
| 3/0 | 0.25 | 噪声 |
| 5/0 | 0.063 | 方向性证据，不显著 |
| 6/0 | 0.031 | 勉强显著 |
| 8/0 | 0.008 | 显著 |

**为什么不能直接比百分比**：

```text
A: 20/30 = 66.7%
B: 23/30 = 76.7%
```

看起来 +10pp，但如果翻转是 b=5、c=2，净翻转只有 3；McNemar p≈0.45，仍然是噪声。  
如果 b=8、c=0，净翻转 8，p≈0.008，才是强信号。

所以「配对」不是统计装饰，它把**同一个 case 的前后变化**从两个独立百分比里救出来。

### 2.5 决策：阈值必须在看数字之前定

事后看数字找理由，是人类最强的能力。预注册就是挡住它。

一个可用的决策卡：

```text
【预注册】draft 不越权写盘 v1
假设：只加「先列候选、不落盘」一条，会让 characters/ 未授权写盘的 case 从 9/30 降到 ≤3/30。
主指标：pass^3（30 case × 3 run）
护栏 1：越权写盘 = 0（安全）
护栏 2：pass^3 不回退
护栏 3：成本 delta ≤ +20%，P50 延迟 ≤ +30%
留出集：10 个 case，调参时不看
通过条件：净翻转 ≥ 6/30 且 McNemar p < 0.05，留出集同向，护栏全过
失败处置：回滚；失败样本进回归集；结论进 ADR
```

注意：

- **主指标只一个**。多个主指标等于没有主指标；
- **护栏不是「顺便看看」**。安全指标回退，即使主指标涨了也不能保留；
- **留出集必须真的不看**。反复看留出集调参，它就不再是留出集；
- **决策是人的动作**，不是模型或 eval 自动做的。

### 2.6 沉淀：失败样本、结论、基线

一次闭环结束，至少留下三样：

1. **失败样本进回归集**：这次修好的失败，下次不能悄悄回来；
2. **ADR / 决策记录**：为什么这么做、放弃了什么、什么条件下该推翻；
3. **新基线**：下一轮实验的对照。

没有沉淀，闭环会退化成「每次从零开始调参」。  
尤其要沉淀**失败的假设**——「这条改动没用」也是结论，不是垃圾。

## 3. 一个完整的 talemate 例子

### 3.1 假设

> 在 draft 模式里加一条「先列候选、不落盘」，会减少模型在用户确认前写 `characters/`。

### 3.2 单变量

只改 `prompts/modes/draft.txt` 里的一个片段：

```diff
+ 用户没有明确选定的角色，先列候选，不要写 characters/。
```

装配后断言：

```text
before_hash ≠ after_hash
替换串命中
```

如果替换没命中，实验直接判「没做成」，不是「没效果」。

### 3.3 重复 + 配对

固定：

- 30 个 draft case；
- 同模型、同温度、同最大输出；
- 每个 case 跑 3 次；
- A = baseline，B = variant。

得到：

```text
A: 20/30 case 的 pass^3
B: 23/30 case 的 pass^3
翻转：b=5（A 败 B 成），c=2（A 成 B 败）
净翻转：3
McNemar p≈0.45
```

结论：**不能保留**。+10pp 的边际差被 3 个净翻转和噪声吃掉了。

如果换一组数据：

```text
b=8, c=0
净翻转=8
p≈0.008
```

才达到「显著」的门槛。

### 3.4 决策

假设主指标显著，但成本从 ¥1.9/章 涨到 ¥2.4/章（+26%），超过预注册的 +20%：

- 不能因为「质量涨了」就忽略成本；
- 按规则：**不保留**，或者改成「先压成本，再重新预注册」。

这就是预注册的价值：它不让你在数字出来后改判据。

### 3.5 沉淀

- 把 b=5、c=2 里失败的 case 收进 `eval/cases/regression/`；
- 写 ADR：为什么这条干预没通过、下一次该改什么；
- 更新 baseline 与噪声地板；
- 下一轮假设从失败桶里长出来。

## 4. 闭环的输入、输出与「回头路」

```text
输入：
  · 一个可推翻的假设
  · 固定 case 集 + baseline
  · 预注册的决策规则

六步：
  假设 → 单变量 → 重复 → 配对 → 决策 → 沉淀

输出：
  · 保留 / 回滚 / 再改的决策
  · 更新后的回归集
  · ADR + 新基线
  · 下一轮假设
```

「回头路」不是失败，是闭环的正常形态：

- 假设被推翻 → 从失败桶里提新假设；
- 决策是「再改」→ 重新单变量，不带着上一轮的多个改动一起上；
- 沉淀发现 case 不合法 → 先修 case，再重跑。

## 5. 常见误解

| 误解 | 为什么错 |
|---|---|
| 「闭环 = 跑一遍 eval」 | 缺假设、单变量证明、噪声、预注册；数字无法变成决策 |
| 「只改一个文件就是单变量」 | 还要证明装配后的字节真的变了；否则变体可能静默退化 |
| 「A 66.7% vs B 76.7%，B 更好」 | 没配对、没看净翻转；3 个翻转在 30 case 上就是噪声 |
| 「p<0.05 就一定保留」 | 还要看安全护栏、成本、留出集；显著性不等于产品价值 |
| 「失败样本不用留」 | 不沉淀就会重复踩同一个坑；失败假设也是结论 |
| 「留出集可以边调边看」 | 看了就不再是留出集，最终数字会过拟合 |
| 「一次闭环必须成功」 | 负结果也是结果；闭环的产物是决策，不是「证明我对」 |

## 6. 自检

1. A 组 20/30，B 组 23/30，为什么不能直接说 B 比 A 好 10 个百分点？请说出配对后的净翻转和大致结论。
2. 「单变量」除了只改一处，还必须证明什么？如果替换串没命中，这次实验的结论应该是什么？
3. 一次闭环结束后，至少要沉淀哪三样东西？为什么失败的假设也要沉淀？
4. 预注册为什么必须在看数字之前写？如果看到 p=0.04 再定阈值，会出什么问题？
5. 30 个 case 的评测集，净翻转 3/30，按手册的判定表应该做什么决策？
