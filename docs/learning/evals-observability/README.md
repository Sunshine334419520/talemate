# 学习目录 · 评测与可观测性

> **职责**：收拢「评测 + 可观测性」这条线的学习材料——原手册、按知识点拆的笔记、进度与问答记录。
> **读者**：正在把这份手册学完的我，以及三个月后忘了「为什么不能只靠 `bun test`」的那个我。
> **对齐代码**：不涉及代码 · 对齐 `handbook.md`（2026-10-30 版）

## 怎么用这个目录

三条规矩，和手册 §0.1 的三条纪律同源：

1. **一个知识点一份笔记**，文件名带序号。笔记不抄手册——抄一遍没有用。笔记只写手册没写透的那一步：这个结论为什么成立、它依赖哪根柱子、我会在哪一步误解它。
2. **每份笔记末尾必有「自检」和「我的误解清单」**。复习时只看这两节；答不对就是没拿下，别往下走。
3. **进度只有一处**：[progress.md](progress.md)。每次学完一个点更一次，不新建「进度2」「进度-最终」。

## 关于 `.dsh-ops-*.lock`

用 DSH 的文件工具改写本目录后，会在这里落一个 0 字节的 `.dsh-ops-update-<hash>.lock`（原子写用的互斥锁，正常应该在收尾时删掉，实际会留下）。它不是资料，随手删掉即可；要让它不再出现在 `git status`，加一行 `.gitignore`：

```
.dsh-ops-*.lock
```

## 关于手册里那几个点不开的链接

手册开头引用了四份相邻文档：`能力评估与补强规划.md`、`deep-dive/part6-evals.md`、`handbook.md`、`learning-roadmap.md`。**它们不在本仓库里**（写手册时在另一个上下文），所以点不开是正常的，不是搬目录搬坏的。原文件保持原样，不做修补——一处改动会让「原文」不再是原文。

## 为什么在 `docs/learning/` 下，而不是 `docs/` 顶层

`docs/` 顶层的约定是「描述**当前状态**」：每份文档开头要有 Status 块，`tests/docs.test.ts` 还会检查它引用的 `.ts` 文件真实存在。

这份手册不是当前状态，是 Stage 1–2 的**计划**：它提到的 `eval/`、`traces/`、`src/trace/` 现在都还不存在。放在顶层时文档守卫持续报两条错——缺 Status 块，以及引到不存在的 `eval/metrics.ts` / `eval/report.ts` / `src/llm/replay.ts`。那两条错是**对的**：它确实在描述一个还不存在的东西。

所以它属于学习区，不属于现状区。搬到这里之后，`docs/` 顶层回到「只描述现在」，学习材料也有了固定的家。以后要学别的手册，在 `docs/learning/` 下新开一个同名子目录即可，不用改这里的任何约定。
