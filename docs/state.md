# 状态层：每章都在变的东西

> **职责**：回答"哪些东西随写作在变、它们存在哪、什么时候写回去"。
> **读者**：要改 `state/` 相关行为的人；以及想知道"为什么它不在 `design/` 下面"的人。
> **对齐代码**：2026-10-14 · 根清单在 `core/config.ts` 的 `DOC_ROOTS`（读口写口共用一份）；`state/progress.md` 的目录行在 `framework/summaries.ts`；第 4 条纪律与 `progress.md` 的 7 章窗口给模型看的那一份在 `prompts/tools/propose-plan.txt` 与 `prompts/planner.system.txt` 的状态回写那一条
> 相邻：`design-docs.md`（四层活文档）· `characters.md`（卡上不装状态）· `outline.md`（序列进度）· `chapter-planning.md`（章末回写挂在规划里）

## 一句话

**四层是"这本书是什么样"，state 是"现在到哪了"。**

## 判据

新增任何一条记载，先过这一条：

> **它会不会因为某一章写完而变？**
> 会变 → 归 `state/`。不变 → 归四层（它是设定）。只在正文里成立、下一次写作也用不着查 → **不存**，正文就是它的家。

**判据比清单要紧**：状态会随写作长出新类目，清单定死了就得改格式，而每次改格式都是一次迁移。

## 三个根

| 根 | 是什么 | 谁看 |
|---|---|---|
| `design/` | 设定——这本书是什么样（四层活文档） | 用户审阅、进版本控制 |
| `chapters/` | 正文 | 同上 |
| `state/` | **当前状态**——谁在场、谁知道什么、伏笔收到哪了 | 同上 |

**state 与作品平级，不在 `design/` 下面。** 两个理由：

- `design/` 的分层轴是**变化频率**（core 极少变 → wiki/characters 慢变 → outline 快变），而 state 比 outline 还快一个数量级——**它每章都在变**。它不是"第五层"。
- 目录结构本身就是那条判据的体现。**想往 state 里写设定的人，看见它与 `design/` 平级会先愣一下**；藏在 `design/state/` 里则没人拦得住，而一旦开始重述设定，两处迟早说两套话。

## 有哪几份

```
state/
  characters/<名>.md    # 一角色一份：他此刻的处境、身上的伤、手上的钱、别人怎么称呼他
  foreshadowing.md      # 伏笔账：埋在哪一章、打算哪一章回收、收了没有
  progress.md           # 最近 7 章的窗口：一章一节，每条两行（内容 / 落），整篇重写
```

**`progress.md` 是窗口，不是档案。** 它只留**最近 7 章**，更早的在 `chapters/` 的正文里——正文本来就是全量记录，这份只是省得你回头读正文。所以它是**整篇 `write`**（把最早的挤出去），不是往后追加。

它**不是不变量管的**：`invariants.ts` 的上钩判据是"违反了会不会造出一份此后工具都读不懂的文档"，而一份很长的流水工具读得好好的——所以这条是**约定**，漏掉一次只是文件长一点，没有东西坏掉。也**不做机械裁剪**：那会让落盘的字节和你看到的 diff 不是同一份。

每条只留两行，因为**另四行在别处已经有一份**：`落下的伏笔` 与 `未落` 是 `foreshadowing.md` 的，`章节末状态` 是角色状态文件的。同一件事记两处，迟早说两套话——第 4 条纪律管的就是这个。

**形状是长的，不是定死的**——**不定义字段，不做校验**。跟角色卡的「自由长尾」同一条纪律：

> 用户提出要加什么就加什么。工具原样保留，不催、不校验。

所以**加一类状态 = 建一个目录或文件，零代码**。要新代码的只有"加一个根"那一件事，而那件事一辈子大概只做这一次。

**写手的写法说明不在 `design_spec`**：那一行如果加（`sections: []`），会命中 `summaries.ts` 的"不分格文档 → 一行首句"分支，把 `list` 里角色状态的小节名换掉——而 `summaries.ts` 明说那张铺法"有用"。所以第 4 条纪律给模型看的那一份挂在**规划 prompt**（`propose-plan.txt` / `planner.system.txt` 的状态回写那一条），写手正是在那一刻写状态文件。

`progress.md` 在 `list` 里只占一行（几条 · 最新一条）——它是只追加的流水，几十章之后整篇铺小节会把目录淹掉，而按 `outline.md` 立的判据，**没有被分别读取的小节就不展开**。

## 四条纪律

**1. 状态引用设定，不重述设定。** 这是状态层最容易长歪的地方——它会不知不觉膨胀成**第二份企划**。"金手指开到哪一步"是设定的边界加上剧情推进：state 里只记**推进到哪了**，边界去引 `design/core.md`。抄一遍，那边一改就说两套话。

**2. 流水是"读"的依据，不是进度本身。** 故事内时间、写到哪儿了都不单独存——它们从 `progress.md` 现读现算：「能算出来的不要存」，存一份进度表，它迟早和实际章节数说两套话，而**脱节的缓存比没有更糟**。状态卡上那行"写到第 3 章（…）"就是这么现读出来的（`report.ts` 的 `outlineBrief`）。**它只报位置不报剩余**——理由见 `roadmap.md` 的「序列进度只报位置，不报剩余」。

**3. 不常驻注入。** `design/core.md` 与 `design/wiki/world.md` 每轮注入，state **不**——它每章都在变，而且只在"写作前那一步"用得上（规划本来就会读它）。常驻等于每轮为一份只在某一刻有用的东西付钱。第 4 条与 `progress.md` 的窗口保证它不随章节长大，但那也不是常驻的理由。

**4. 状态记"现在"，不记"来历"。** 添一行之前先过一句：**这一行描述的是"现在"，还是"发生过什么"？**"现在"留着——它约束下一章怎么写；"发生过什么"归**正文**（它本来就是全量记录），或者哪儿都不去。

- **解掉的删掉，不写墓志铭。** 翻过去的墙、学到的事、了结的账——**删**，不是加一句"已解决"。墓碑正是让状态文件读起来像流水的东西：`碰过的壁` 里挂着一条"（第五章解掉了）"，那已经不是墙了。
- **逐章流水归正文与那 7 章窗口。** 角色状态里"第一章…第六章…"那种一章一条的格，正文里有一份、`progress.md` 的窗口里也有一份；两处记同一件，迟早说两套话。第 1 条讲"不重述设定"，这条讲"不重述来历"——同一个毛病的两个方向。

**它管的是文件的增长律。** 快照型的格（"眼下的处境"）天然有界，累积型的格天然无界；按这条逐行筛过之后，一份角色状态的规模从 **O(章数)** 落回 **O(还活着的事实数)**——一百章之后仍是几十行，因为它记的是"现在"。

## 回写

**章末，mate 自己写**（正文归它了，`write` 的结果直接回到它手里——从前这一步卡在"章节在 writer 子会话里落盘"上，那个障碍随 writer 一起消失了）。

- **时机写在规划里**：`propose-plan` 的「产物（按序）」把状态回写列成第 2 项，所以它是**这一次执行**的一部分，不是事后补的。
- **走二向的 `write` / `edit`**：用户看 diff 点头。不走 `propose-design`——那是作品文档的三向通道，而状态每章都变，为它跑一遍"接受/拒绝/提意见"太重。
- **是软纪律**（不回没人拦）。硬门在这里买不到东西：回写错了不会崩，只会让下一次写作读到旧状态，而那正是 `read` 与规划要发现的。

## 明确不做的

| 不做 | 为什么 |
|---|---|
| **字段 schema / 校验** | 第一次遇到"该记的东西没地方放"就得改格式，而每次改格式都是一次迁移 |
| **单独的进度表** | 能算的不要存 |
| **自动回写 agent** | 那正是被否决的「后台自动改企划」——改动走 mate 提议、用户拍板 |
| **一致性对账** | `roadmap.md` 的 P4 是另一件事：**读**，不是写 |
