# 人物层：角色卡

> **职责**：回答"角色卡是什么、为什么在写第一次出场前要有、怎么写才算好、名单和状态怎么分工"。
> **读者**：要改 `src/framework/design_guides.ts` 的角色指南、`src/framework/characters.ts` 的名单助手，或写角色相关提示词的人。
> **对齐代码**：2026-11-23 · 卡不再有必填格/骨架校验；形状由设计指南引导，名单只取首句。状态与知识边界在 `state/`（见 `docs/state.md` 与 `docs/information-model.md`）。
> 相邻：`design-guides.md`（设计指南总则）· `information-model.md`（对象/真源）· `state.md`（当前状态）· `design-docs.md`（四层与两段式）

## 一句话

角色卡是**行为合同**，不是人物传记：它约束“这个人下一次怎么选、怎么说话”，而不是把已写过的内容抄一遍。

## 为什么必须在第一次出场前写

卡的用途是约束还没写的场景：他会怎么选、什么绝不做、开口是什么声音。事后从正文反推出来的卡只是墓志铭——对下一章没有约束力。所以规划里点到一张还不存在的卡时，建卡排在正文之前。

## 一份好卡回答什么

不要求固定小节，也没有“缺一即拒”。指南问的是：

1. **他想要什么？** 具体到能驱动行动，不是“想变强”。
2. **他最怕什么？** 恐惧决定压力下的选择。
3. **他绝不做什麼？** 否定式约束，防 OOC。
4. **他说话是什么声音？** 必须给**一句可验伪的原话**，不是“说话冷淡”。
5. **他身上的矛盾是什么？** “既…又…”；这是选择的来源。
6. **他的能力/限制如何塑造选择？** 能力即性格，不是技能表。
7. **别人怎么称呼他？** 别名/称谓（grep 与连续性用）。

模型可以用任何结构回答：几段散文、几个小标题、一段独白都行。**回答得上就是好卡。**

### 好例子

```markdown
# 角色：林晚

二房庶女，管着家里的账，却始终不被允许坐上主桌。

她想要账册，不是为了钱，是为了让二房在族老面前没法再说她“只是个丫头”。
她最怕被当成二房争产的棋子；所以先算账，再叫人。

“二爷的账，什么时候轮到外人看了？”——她对二房以外的人，永远先问这一句。
她绝不让人看见她哭。
```

### 反例

- 形容词堆（“英俊、冷酷、聪明”）；
- 简历/年表（“三岁丧母，七岁习武”）；
- 当前处境（在 `state/characters`）；
- 关系（谁欠谁、此刻盟友还是敌人；那是状态/情节）；
- 事件（“他在第 3 章杀了 X”）；
- 没有一句可验伪的台词；
- 把“他很强”写成技能列表。

### 尺寸

建议 300–1200 字，决策级。超了先问自己：这一笔会改变哪一场的选择或哪一句话？没有答案就删。

## 卡上不装什么

| 不进卡 | 去处 |
|---|---|
| 当前处境：在场/已故/伤势/钱 | `state/characters/<名>.md`（每章回写） |
| 谁知道什么 | `state/knowledge`（命题 × 人，提议） |
| 关系：谁欠谁、此刻盟友/反目 | `state/relations`（提议）或正文/大纲 |
| 事件/章号 | 正文与 `state/progress` |

**知识边界必须单点。** 把“A 知道、B 不知道”分散到 N 张卡上，就是 N 份副本；跨角色一致性没有机制能保证。

## 谁需要一张卡

判据不是“出场了没有”，而是——**下一章还可能用到他，而且需要他前后一致吗？**

| | 例子 | 去处 |
|---|---|---|
| **不会再用** | 茶馆伙计、传令的驿卒 | 不建卡；正文里写清楚即可 |
| **还会再用** | 这一卷反复出现、有台词、有立场的人 | 要卡，且在第一次出场那一章之前 |

**规划不许自己造人。** 需要一个人兑现功能而文档里没人担得起时，规划只写“这一步需要一个人做 X”，名字由用户给。

## 名单行

`list` 的角色段一人一行，现算：

```
- 林晚 · 二房庶女，管着家里的账
```

- 取卡内**第一句有内容的正文**；旧卡的「键：值」行取值（`姓名：林晚` 与卡名相同则跳过）。
- 不显示“必有齐/待补”——卡没有必填格。
- 没有派生总表；名单由卡现算。

## 维护模型

| 类 | 内容 | 复核时机 |
|---|---|---|
| **合同** | 想要/最怕、底线、声音、矛盾 | 按卷复核；人物成长时和用户一起改 |
| **自由正文** | 用户/模型认为需要的任何形状 | 无固定节奏 |
| **状态**（不在卡上） | 在场/已故/处境；谁知道什么 | 每章回写到 `state/` |

## 写入路径

- **建卡 / 整篇重写**：`propose-design` 带 `path: design/characters/<名>.md`；用户看整篇（重提看 diff）后拍板。
- **改一段**：`edit`，锚点就是那段原文；用户看精确 diff。
- **删卡**：`delete`，先列出“这个名字还在哪儿出现”，级联清理由模型用 `edit` 做。
- 没有角色专用工具；卡的“角色性”只在指南与名单助手，不在额外工具。
