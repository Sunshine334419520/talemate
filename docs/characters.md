# 人物层：角色卡

> **职责**：回答"角色卡长什么样、怎么维护、mate 在角色设计上做什么"。
> **读者**：要改 `framework/characters.ts`、角色相关守卫，或定角色设计规范的人。
> **对齐代码**：2026-09-23 · 工具面与不变量在 `src/tool/` 与 `src/framework/invariants.ts`
> 相邻：`design-docs.md`（四层与两段式落盘）· `roadmap.md`（状态目录还没做）· `product.md`

## 一句话

角色卡是**长期动态维护的活文档**：它要跟着小说正文一直变。所以第一性问题不是"该填哪几格"，而是"**这一格随时间怎么变**"。

## 卡的形状：必有五格 + 自由长尾

```
# 角色：<名>

### 基本档案          ← 必有；逐行「键：值」，键固定、可扫描
姓名 / 性别 / 年龄段 / 籍贯 / 职业 / 身份 · 所属 / 相貌
### 性格与矛盾        ← 必有
### 想要 · 最怕       ← 必有
### 底线 · 绝不做     ← 必有
### 说话方式          ← 必有（含一句范例原文）

### <用户要求加的任何节>   ← 自由长尾
```

**必有五格**（`CHARACTER_FIELDS`）：整篇提案缺一即拒。每格装什么：

| 格 | 装什么 |
|---|---|
| 基本档案 | **逐行「键：值」**。它不是把格子拆开，而是给这一格一个可扫描的形状——一眼看得出缺哪一项 |
| 性格与矛盾 | 写成「既…又…」的矛盾，不是形容词堆 |
| 想要 · 最怕 | 欲望与恐惧——行动引擎 |
| 底线 · 绝不做 | 否定式约束，防 OOC。**好角色压不进一句话，但压得进"ta 绝不做 X"** |
| 说话方式 | 语域 / 口头禅 / **声音范例原文** / 对谁不一样 |

**性格 / 想要 / 底线 / 说话方式不放进基本档案**：它们要写成有写法的段落（矛盾、一句范例原文），塞进「键：值」的一行会撑破那张表的可扫描性——所以各自成节。

**自由长尾**：用户提出要加什么就加什么（世界特有的格，如「回响」）。工具**原样保留**，不催、不校验、不进骨架。

### 硬约束：卡上只许 `###`

`proposal.ownItems` 取**最浅**标题层。卡上冒出任意一个 `##`，全部 `###` 就都从提案审阅里消失——用户没看过的字节直接落盘。

所以**任何**往卡上写 `##` 的动作都拒：这条落在 `invariants.ts` 的 `characters.no-shallow-heading`，
判的是**算出来的结果**——于是 `write` / `edit` / `append` / `propose-design` 没有哪条绕得过
（从前它只挡在 `propose-design` 与 `append-design` 两处，`edit` 是敞的）。

## 好卡的标尺

以《十日终焉》乔家劲的人物卡为准，五条可判据：

| # | 判据 | 例子 |
|---|---|---|
| 1 | **性格写成矛盾**，不是形容词堆 | 「虽是混混，却不愿伤人性命」 |
| 2 | **每笔都是能被用到的道具**，不是简历 | 背上纹的「天地本宽，而鄙者自隘」会在打斗脱衣时被读到 |
| 3 | **能力即性格** | 回响契机「想要公平地进行对决」——性格被写成机制 |
| 4 | **声音锚必须可验伪**，载体是「说话方式」里的一句范例原文 | 新人写一句台词，能拿范例比出对不对；形容词比不了 |
| 5 | **卡是有时间的** | 状态会变（见下：状态不在卡上） |

**这把尺子量的是决策级，不是句子级**：正确的判据是"这一笔能不能改变**他在某个情境下的选择或说法**"。用句子级去量会把卡饿死（`生于1979年` 不改任何一句话，却决定他每次开口的词汇与对暴力的反射）。

## 卡的领域性全在"读与校验"一侧

**角色卡一个专用工具都没有了。** 建卡与整篇重写走 `propose-design` 带 `name:"characters/<名>.md"`；改一格走通用的 `edit`（锚点就是那一格的正文）；删卡走通用的 `delete`。

它的"角色性"落在**读与校验**这一侧：

| 机制 | 在哪 |
|---|---|
| 必有五格的清单（单一真相源） | `framework/characters.ts` 的 `CHARACTER_FIELDS` |
| 骨架校验（整篇写缺格即拒） | `framework/invariants.ts` 的 `characters.skeleton-complete` |
| `##` 守卫 | `framework/invariants.ts` 的 `characters.no-shallow-heading` |
| 必有格只能清空、不能整格消失 | `framework/invariants.ts` 的 `characters.required-kept` |
| 整篇重写告警 | `design_tools.ts` 的 `cardRewriteWarn` |
| 名单行 | `framework/anchor.ts` 的 `characterLine` |

三条不变量都判**算出来的结果**，所以 `edit` / `append` / `delete` 哪条路都绕不过——从前它们只对着
`propose-design` 的提案文本跑，另外几条路是敞的。

**骨架校验与内容判定是两个口径**：`characters.skeleton-complete` 只看**标题在不在**（写个空标题能过）；内容空不空由名单行的「待补」判（`pendingRequiredLabels`）。

## 名单行

`list-designs` 对角色卡一人一行，三段全**现算**：

```
- 沈越 · 码头搬运工（必有齐；另有：回响、能力 · 机制）
- 周渡 · 港务局职员（待补：底线 · 绝不做）
```

- **身份**取「基本档案」里 `身份 · 所属` 那一行的值（有回退链，见 `cardIdentity`）
- **必有齐 / 待补：…**：哪几个必有格的内容还是空/（待定）
- **另有：…**：自由长尾的小节标题

「另有」的意义：**不把卡读进上下文，也能看出"这个人卡上除了必有格还有什么"**。目录要廉价，正文才昂贵。

> 这条规矩**推翻**了早期"角色卡不铺小节标题"的说法——那时不铺是对的（每张卡都有同样的固定格，列出来是纯噪音）；现在长尾每张卡都不同，它才是信号。

**没有派生总表**：名单每次现算，数据源只有卡本身。曾经有过一个 `characters/_index.md`，它是卡的副本——副本会脱节（走 `propose-design` 落卡就不更新），已删除。

## 卡上不装状态，也不装关系

三类东西**不进卡**：

| 不进卡的 | 例子 | 去处 |
|---|---|---|
| **点形快变量** | 在场 / 已故 / 此刻处境 | `design/state/`（**未实现**，见 `roadmap.md`） |
| **边形** | 谁知道什么（角色×秘密） | `design/state/continuity.md`（**未实现**） |
| **关系** | 谁欠谁什么、ta 怎么看谁、此刻是盟友还是反目 | **细纲与正文**（不进任何设计文档） |

- **快变量**是"读的时候要最新的"，混在卡里必然腐烂——回写机制不存在时更是如此。曾经卡上有个工具托管的「当前」格，已删：它的写入方（章末回写）从未实现，实际上永远是占位。
- **边形与关系是跨角色的**，而**跨角色的一致性，局部文档在原理上保证不了**：分散到 N 张卡上就是 N 份要同步的副本——"A 卡说他知道了、B 卡说他不知道"是迟早的事，且没有任何机制会发现。所以边形的值必须**单点化**；关系则干脆不进设计文档，它本来就是情节层的素材。

## 维护模型

| 类 | 内容 | 复核时机 |
|---|---|---|
| **不变量** | 基本档案 | 定了基本不动；**乱动 = 吃书**，必须过用户 |
| **慢变量** | 性格与矛盾、想要·最怕、底线·绝不做、说话方式 | **按卷复核**（人物成长就是这几个在变） |
| **自由长尾** | 用户加的任何小节 | 无固定节奏——用户提出来才动 |
| **状态**（不在卡上） | 在场/已故/处境；谁知道什么 | **每章回写**（未实现） |

## mate 在角色设计上的定位

> **mate 是"让用户笔下的人能开口"的导演——他提炼、试镜、守合同、管档案；他不造人、不填表、不写正文。**

| 定位 | 做什么 |
|---|---|
| **提炼者** | 用户带来一个模糊的人 → 帮他钉住能写的那几笔 |
| **试镜导演** | **别问"他性格是什么"，让他开口**：给一句台词，让用户听声音对不对。用户说"他不会这么说话"的那一刻，才真在设计角色。试镜稿是设计草稿、不是正文 |
| **一致性守门人** | **卡是用户签过的合同**。用户说"她这时候该心软了"而卡上写着「最怕被看穿」时，把冲突摆出来问：**改卡还是改戏？** |
| **档案管理员** | 每章定稿后做一次人物对账，把这一章引起的变化回写（未实现） |

## 完整加载

**写作要用到某个人，就是整张卡都要用。** 没有"只加载常驻带"这回事——曾经有过一个切片工具，已删除：它存在的理由是"按需格只在用到时付 token"，而**那半句从来没有代码**（没有任何按需格切片 API），实测也从未被调用过。

代价是卡必须有**尺寸纪律**——但目前没有任何机制约束它（见 `roadmap.md`）。
