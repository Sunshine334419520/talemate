# 路线图与已知缺口

> **职责**：回答"还没做什么、哪些地方是已知的坑、哪些决策还没拍板"。
> **读者**：要决定下一步做什么的人。
> **对齐代码**：2026-09-29 · 本文记的都是**当前不存在**的东西；写完就删掉对应条目
> 相邻：`product.md`（演进方向）· `state.md`（状态层，已落地）· `characters.md` · `design-docs.md` · `chapter-planning.md`

## 已确认的缺口

**状态层与伏笔登记已落地**（见 `state.md`），不再记在这里；这一节只剩还缺的东西。

### 卡会长到多大

现在的前提是"卡被完整加载"，所以卡必须有尺寸纪律——**但没有任何机制约束它**。自由长尾是"用户提出来就加"，加多了整张卡就贵。

可能的答案：`list` 的名单行报个字数，或者给个软上限提示。目前只是记录，不做。

## 已拍板但值得回看的取舍

这些不是"待办"，是**已知的代价**——记在这里是为了下次有人提同样的问题时，知道已经想过了。

### 序列进度只报位置，不报剩余

"写到哪个序列的哪里了"有两个问法，**只有一个答得出来**：

| 问法 | 做法 |
|---|---|
| **位置**——写到第几卷、第几个序列、最近一章推进了什么 | **已做**：`report.ts` 的 `outlineBrief` 现读 `state/progress.md` 的最后一节报出来 |
| **剩余**——这个序列那几件事兑现了几件 | **不做**，理由见下 |

**"剩余"算不出来。** 序列纲声明的是**功能**不是事件（"给主角一个进内城的理由"，不是"主角遇到老乞丐"），
而它自己也写着"一节要写成几章，是写到那儿才知道的"。所以章数与"这个序列兑现到哪了"之间**没有换算
关系**——报个百分比、或者"还剩 3 章"，都是编。

要让它变得可算，只有一条路：**给序列纲加一份可勾的清单**。但 `outline.md` 明确否掉了那个写法
（"清单把事件钉死，而事件随时可以换、只有功能稳定"）——**为进度推翻语义，代价不对**。

它今天由**规划者现读现判**：写第 N 章规划时本来就要读序列纲，顺手就判断了"这一段还剩什么、这一章
钉哪一件"。而且这么做**每次现读，天然不脱节**——比存一份进度强。

**什么情况下回头重开这一条**：实测发现规划者老判错（把已经写过的功能又兑现一遍）。那时该动的是
序列纲的写法，或者真的给它加清单——**那是一次设计决定，不是加一层"进度计算"**。

### 文档层不建 ADR

历史决策（"曾经这么想、现在不这么想"）随旧文档一起删除，只在 git 历史里。**代价**：想追溯"当初为什么否掉某个方案"，得去翻 commit。

被删掉的具体内容：产品定义的 Q1-Q16 决策记录、旧架构图与领域模型、harness 的早期设计附录、角色层的分期实施史。

### 「待定」的写法没有硬约束

真实草稿里出现过 `（内容（待定））` 这种括号套括号，工具认不出来，那一格会被当成"填了"。目前只认 `（待定…）` 与 `键：（待定…）` 两种。

### 世界特有的格是否需要一层"声明"

自由 `###` 完全自由；跨项目复用（如"系统流"的固定格）暂无机制。

### 考据本：命中会压制重查，而且它每本一份

`researcher` 查回来的结论现在会落到 `<novel>/.talemate/research/`（见 `agents.md` 的 `research_tools`），下次先翻它、命中就不上网。三条**明知兑换出去**的代价，记在这里免得下次有人当成 bug 去"修"：

- **缓存是"某天查过的断言"，不是事实。** 一条错的或过窄的笔记会被一次次信下去——命中即返回，就不会再上网核。缓解全在契约里（每条命中都带「查于」日期与出处、"命中是线索不是答案"、覆盖时点名换掉的是哪一版），**没有机制性保证**。要机制，就得给笔记加稳定/易变的类型标记与过期策略——那是一次设计决定，不是打补丁。
- **漏记看不见。** 记什么由研究员自己判断（不是每次查询都记），所以"该记而没记"不报错、也没有痕迹，症状只是下次又查一遍。
- **每本一份，不跨书。** 第二本写明代的书写会把同样的东西再查一遍。全局层要的是**合并**语义（两本书两条冲突的笔记怎么仲裁），而 skill 库那套是"同名覆盖"——语义不通，不是把目录挪个位置的事。
- **mate 自己的一次性 `webfetch` 既不查也不落。** 缓存只挂在 research 这一层（联网工具保持纯粹：把"这条查过没有"塞进它们，它们就不再是"给参数就给结果"的东西了），而 mate 那条路的判据本就是"一个问题一次查询就定、不值得派研究员"。代价：那种小事实仍会重复查。

**什么情况下回头重开这一条**：实测发现研究员老判错（该用的没用上、或明显过时了还在返回），或者同一本书的笔记多到 `recall` 的命中清单已经不好读。前者该动的是排除规则或那条"命中是线索"的措辞，后者才是给 `recall` 加上限。
