# 路线图与已知缺口

> **职责**：回答"还没做什么、哪些地方是已知的坑、哪些决策还没拍板"。
> **读者**：要决定下一步做什么的人。
> **对齐代码**：2026-09-20 · 本文记的都是**当前不存在**的东西；写完就删掉对应条目
> 相邻：`product.md`（演进方向）· `characters.md` · `design-docs.md`

## 已确认的缺口

### 状态层（长篇独有）

角色状态目前**无处安放**：卡上不装（见 `characters.md`），独立目录也还没建。

| 项 | 目标 | 已知的落法 |
|---|---|---|
| `design/state/` 承载角色的点形快变量 | 在场/已故、此刻处境 | 走**开放文档**（`propose-design` 的 `name` 分支），按 `wiki/<题>.md` 的先例 |
| `design/state/continuity.md` 承载边形 | 谁知道什么（角色×秘密） | 同上，只收一节 `## 此刻知道什么` |
| **章末回写** | 每章定稿后把变化写回状态 | 契约挂在 `task` 结果上（仅 `agent === "writer"`）——章节在 writer 子会话里落盘，`save-chapter` 的结果到不了 editor，唯一到得了的是 `<task_result>` |

**不要做成第 5 个 `LayerId`**——会连带 `LayerId` 联合、`DESIGN_SPECS` 穷尽、`report.ts` 四层卡片、`resolveDoc` 的 `MAIN_LAYERS`、`design-spec` 白名单。

**必须改 `framework/anchor.ts` 里 `buildDesignIndex` 的硬编码分组顺序** `["", "wiki", "characters", "outline"]`——不加 `"state"`，它在 `list-designs` 里**根本不出现**。写入本身不用改白名单：`writeDesign` 的 `mkdir recursive` 会自动建目录。

**首次成稿必须是整篇提案**：小节级提案要求文档与小节都已存在。

**未定的形状**：一角色一文件（`state/<名>.md`）还是单文件分小节？前者贴合"引用关联这个角色卡"，后者少一堆文件。

**回写是软纪律还是硬门禁**：倾向软，与"写章前先有已批准细纲"同类。

**序列进度也挂在这一环上**：序列纲声明它要包含什么，每章定稿时回写"推进到了哪一步"，
规划下一批时现算剩余。所以章末回写不只是给 `continuity.md` 用的——它是**序列纲与章计划之间
唯一的数据源**（见 `outline.md`）。没有它，"AI 知道我们写到哪个序列的哪里了"就只能靠数章数，
而章数是会漂的。

### 章计划不进 `design/`，但落点未定

方向已经定了（2026-09-20）：**章计划不该放在 `design/`**——它不经过用户拍板，而 `design/` 的
全部意义是"用户看过的字节 == 落盘的字节"（`design-docs.md`）。**序列纲是用户能拍板的最小结构
单位**，章计划是拍板之后的执行细节，是序列纲的一个投影。

但放哪没定：`chapters/` 之下？跟着会话走（写完即弃，反正细纲本来就是消耗品）？它和"序列进度"
是同一件事的两面，一起设计。**现在它仍躺在 `design/outline/plan_ch<N>.md`。**

### 伏笔与回收登记没有家了

它是初版 `outline.md` 五格里**错层的那一格**：每章都在变、必须按章检索，属于**事实**而不是
**设定**——和 `continuity.md`（谁知道什么）是同一类东西。`anchor.ts` 的模块注释里早就写着
"状态类信息（写作进度/**伏笔**/待定）不是静态基线"，但 `design_spec.ts` 一直把它放在情节层。

现在它随旧 `outline.md` 一起删了，**落点跟着状态层一起定**。

### 卡会长到多大

现在的前提是"卡被完整加载"，所以卡必须有尺寸纪律——**但没有任何机制约束它**。自由长尾是"用户提出来就加"，加多了整张卡就贵。

可能的答案：`list-designs` 的名单行报个字数，或者给个软上限提示。目前只是记录，不做。

## 已拍板但值得回看的取舍

这些不是"待办"，是**已知的代价**——记在这里是为了下次有人提同样的问题时，知道已经想过了。

### 文档层不建 ADR

历史决策（"曾经这么想、现在不这么想"）随旧文档一起删除，只在 git 历史里。**代价**：想追溯"当初为什么否掉某个方案"，得去翻 commit。

被删掉的具体内容：产品定义的 Q1-Q16 决策记录、旧架构图与领域模型、harness 的 opencode 对照附录、角色层的分期实施史。

### `save-chapter` 归谁

两条路**二选一，不能都留**：

- **拿掉 writer 的 `save-chapter`**：writer 只回传正文文本，editor 收到后落盘，confirm 落在 editor 层。代价：长章节整篇进 editor 上下文。
- **保留**：writer 长文直接落盘、只回摘要，省 editor 上下文；但 confirm 在子会话里弹，editor 对成品的把关变弱。

当前保留 writer 的 `save-chapter`。折中落点（未采纳）：writer 落盘 + 回传短摘要 + 文件路径。

### 「待定」的写法没有硬约束

真实草稿里出现过 `（内容（待定））` 这种括号套括号，工具认不出来，那一格会被当成"填了"。目前只认 `（待定…）` 与 `键：（待定…）` 两种。

### 世界特有的格是否需要一层"声明"

自由 `###` 完全自由；跨项目复用（如"系统流"的固定格）暂无机制。
