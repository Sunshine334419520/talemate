# 情节层：卷纲与序列纲

> **职责**：回答"大纲由什么构成、一卷的纲/一个序列的纲各写什么、为什么没有整本大纲"。
> **读者**：要改 `framework/design_spec.ts` 的 `outline` 与 `DOC_SPECS`、或改情节层写入守卫的人。
> **对齐代码**：2026-09-20 · 规范在 `framework/design_spec.ts` 的 `DOC_SPECS`，匹配在 `proposal.specFor`
> 相邻：`design-docs.md`（四层与两段式落盘）· `characters.md`（另一个"主文档是目录"的层）· `roadmap.md`

## 一句话

情节层**只有两个尺度**：**卷**（一个完整的故事）和**序列**（一个情节单元）。
没有"整本大纲"这个文档——它是**能算出来的东西**，存一份下来只会脱节。

## 为什么没有整本大纲

初版有一个 `design/outline/outline.md`，放着五格：一句话主线 / 开篇钩子 / 分卷方向 / 结局方向 /
伏笔与回收登记。推翻它，是因为**那五格没有一格真正需要一个"全书大纲"文档**：

| 旧那一格 | 现在的家 |
|---|---|
| 一句话主线 | core 的「一句话简介」——且那版更具体（谁 × 要什么 × 挡着什么） |
| 开篇钩子（前 3 章） | 就是头几章的章计划 |
| 分卷方向 | 就是卷纲本身 |
| 伏笔与回收登记 | 状态层（`design/state/`，**未实现**，见 `roadmap.md`） |
| 结局方向 | core 的可选格——**用户想好了才填**；没想好就不该有这一格 |

判据是仓库一贯那条：**能算出来的东西不要存**（`CLAUDE.md` 的「Never hand-copy a list that can be
derived」、角色名单现算、`design-docs.md` 的「绝不缓存旧设定」）。全局观 = core 的"主角要什么" +
各卷卷纲"已经走到哪"——**它是每次规划新卷时现算的，不是存下来的。**

顺带一个对的结果：存下来的全本大纲一定会被写作推翻，而**脱节的缓存比没有更糟**——它会误导写手。

## 卷纲

`design/outline/vol_<N>.md`，五格。**一卷 = 一个完整的故事**：有自己的目标、冲突、收束，
同时把主线往前推一步。

| 格 | 一句话 |
|---|---|
| 本卷在全局的位置 | 承接上一卷的什么、把主线推到哪 |
| 本卷目标与阻力 | 要拿到什么 + 谁挡着 + 比上一卷难在哪 |
| 本卷的情绪曲线 | 读者的情绪怎么走 + 爽点是哪种类型、落在哪一段 |
| 卷末状态 | 写完这一卷，主角和世界变成什么样 |
| 本卷的序列 | 分几段、每段一句话；末尾给预估字数 |

两条判据值得单独说，它们都是"改纲时会不会崩"的防线：

- **「卷末状态」写状态，不写事件。** 「主角打败了 X」是事件，「主角从无人知晓变成沈家盯上了他」
  是状态。**事件可以换，状态必须保住**——这就是改纲的正确姿势：换事件、保状态。
- **「本卷的序列」不写章号，也不展开每段。** 章数是**写出来的结果**，不是计划里的东西；
  细节写到那个序列再展开（各自一个文件）。

`预估体量` 并进「本卷的序列」而不是单独一格：那一格本来就在讲"分几段"，段数与体量是同一件事。

## 序列纲

`design/outline/vol_<N>/s<序号>.md`。**整篇散文，不分小节**——一个序列本来就该一口气说完。

`sections` 为空是**故意的**（与角色卡同路：形状全在 `guide` 里）。逼它分格是削足适履，
而且"必含 A、B、C"式的清单会把事件钉死——**只有功能稳定，事件随时可换**：

> 写功能（「给主角一个进内城的理由」），别写事件（「主角遇到老乞丐」）。

要写的是四件事：这个序列讲什么、大致怎么走、哪几处不能写坏、预估体量。

## 目录与寻址

`list-designs` 里，**卷纲列它的五格，序列纲只给一行 + 首句**：

```
  outline/
    vol_2.md:
      - 本卷在全局的位置
      - 本卷目标与阻力
      - 本卷的情绪曲线
      - 卷末状态
      - 本卷的序列
    vol_2/s1.md（主角混进沈家的夜宴，为的是拿到那本账册。）
```

判据：**只有当同一文档内部的小节会被分别读取时，目录才列小节。** 卷纲的五格会被单独
`propose-design` 带 `section` 改，所以列；序列纲整份读，所以不列。角色卡一人一行是同一个道理。

**写入一律走 `name`（`outline/vol_<N>.md` / `outline/vol_<N>/s<序号>.md`），不走 `layer`**：
`DESIGN_SPECS.outline.file` 是目录 `"outline/"`（和 `characters/` 一样永不精确匹配），
所以 `layer:"outline"` 会被 `resolveDoc` 拒掉，并把正确路径给回去让它自纠。

**规范按路径模式登记**（`DOC_SPECS`），不是按目录前缀推断——同一个层下有几种文档时，
只有模式分得开卷纲与序列纲。取规范：`design-spec` 带 `layer:"outline"` 拿两份，
带 `name` 拿其中一份。

## 尚未落地

- **章计划仍在 `design/outline/plan_ch<N>.md`**。方向已定：**它不该进 `design/`**——它不经过
  用户拍板，而 `design/` 的全部意义就是"用户看过的字节 == 落盘的字节"。落点未定，见 `roadmap.md`。
- **序列进度**（写到这个序列的哪一步了）没做。设想的链是：序列纲声明 → 每章定稿章末回写 →
  规划下一批时现算剩余。中间那环挂在 `roadmap.md` 的「状态层」上。
