# 情节层：卷纲与序列纲

> **职责**：回答"卷纲/序列纲各回答什么、怎么写才算好、为什么没有整本大纲、章规划在哪"。
> **读者**：要改 `src/framework/design_guides.ts` 的情节指南、`src/framework/plan.ts` 的章规划工件，或写规划提示词的人。
> **对齐代码**：2026-11-23 · 卷纲/序列纲不再有必填格；指南只给问题、范例与反例。章规划仍在 `.talemate/plans`。对象与真源见 `information-model.md`。
> 相邻：`design-guides.md`（设计指南总则）· `characters.md`（人物层）· `state.md`（承诺的实际状态）· `chapter-planning.md`（章生产）· `perception.md`（每一步怎么选材料）

## 一句话

情节层只有两个尺度：**卷**（一个完整阶段故事）和**序列**（卷内一个完整情节单元）。两者都是**契约**：约束“结束时什么必须为真”，不是剧情梗概。

没有“整本大纲”：主线是什么归核心层的一句话简介，走到哪了由各卷卷纲与状态现算；存一份下来只会脱节。

## 卷纲

### 为什么要有

一章可以写得很好，但十章加起来不成为一个“卷”。卷纲约束的是：**这一阶段结束时，什么不可逆地变了；这一阶段欠读者什么、不能提前揭什么。**

### 一份好卷纲回答什么

1. **独立故事问题**：谁想要什么、谁挡着、失败会失去什么；为什么是现在；和上一卷的差异、主线增量。
2. **目标与阻力**：对手的目标/资源/反扑；升级轴；失败代价；本卷上限。
3. **卷末状态**：用状态写，不用事件写；至少一轴不可逆（信息/关系/资源/位置/认知/力量）。
4. **承诺**：旧债（兑现/推进/延期）、新债（预计何时还）、禁揭（3–5 条）。
5. **序列**：3–6 段的功能（不是事件）、不可逆转折、线程、承诺；卷末高潮落在哪一段。
6. **情绪节奏**：主情绪、中高潮/低谷/高潮、喘息、卷首钩子。（参考，不是合同）

### 好例子

```markdown
这一卷的独立问题是“沈越能不能在沈家站住脚”，不是“他能不能报仇”。

卷首他是被逐出家门的弃子；卷末他成了族老不得不承认的账房先生，但代价是林晚知道遗言。

目标：查清账册。阻力：二房与族老。升级轴：从查账到被当成争产的人。
失败代价：再次被逐出，且失去林晚。本卷上限：不能碰十年前车祸的幕后。

旧债：母亲留下的那封信。新债：账册是抄本。禁揭：十年前车祸的幕后。

序列：混进夜宴（拿账册）→ 账册失窃（被栽赃）→ 族老审账（反转）→ 卷末选择（烧掉抄本保林晚）。

情绪：压抑里偶尔的爽点；卷末不靠打赢，靠选择。
```

### 反例

- 事件清单（“主角遇到老乞丐，拿到地图”）；
- 章号（章数是写出来的结果）；
- 承诺台账的实际状态（那在 `state/foreshadowing`）；
- 只写打赢/打输，不写代价；
- 把序列写成每章的节拍表；
- “这一卷很精彩”这类评价。

### 尺寸

建议 1–2 页。没有必填格；写到哪算哪。

## 序列纲

### 为什么要有

卷纲管一个阶段，章规划管一场戏；中间缺一个尺度：**几个章节组成的一个完整情节单元**。没有它，卷就是一串章，章规划也没有父契约可投影。

### 一份好序列回答什么

1. **功能**：在卷里承担什么；推进哪条线程；兑现/埋下哪条承诺。
2. **问题**：这一小段谁想要什么、谁挡着、失败会失去什么；必须能脱离整卷单独成立。
3. **入口 → 出口**：入口写关键前提（处境、资源、关系、谁知道什么、什么威胁悬着）；出口写结束时什么是真的，以及如何引出下一段的问题。
4. **不可逆转折**：从什么变成什么（行动/认知/关系/处境/力量/身份），谁选择，代价是什么。
5. **承诺**：兑现哪条旧承诺、埋下哪条新承诺、什么不能提前揭。
6. **写法约束**：哪几处不能写坏；世界规则/战力上限/知识边界；哪些事件可以换。
7. **体量**：参考，不是章数。

### 好例子

```markdown
功能：给沈越一个进内城的理由，并让林晚第一次怀疑他。

入口：沈越有夜宴请帖，但没有账册；林晚以为他是二房的人。
出口：沈越拿到账册抄本，林晚知道他撒谎；“合作”变成互相利用。

不可逆转折：沈越为保账册，把林晚推出去挡了族老的人；她记住了。
承诺：埋下“账册是抄本”；兑现“林晚查沈越的底”。

写法约束：夜宴座次按房头；二房不坐主桌；沈越不能在这里用遗言。
体量：3–5 章。
```

### 反例

- 事件清单（“主角遇到老乞丐”）；
- 章数/节拍表/镜头调度；
- 把“功能”写成事件（好：给主角一个进内城的理由；坏：主角遇到老乞丐）；
- 入口和出口状态相同（那它们其实是同一个序列）。

### 尺寸

建议 300–800 字。

## 没有必填格

卷纲与序列纲是**自由正文 + 指南问题**。模型可以用任何结构回答；`list` 有标题就列标题，没有就取首行/首句。机器要用的东西（章型、承诺状态）不塞进这两份文档：

- **章型**：由 `task` 入参或 `ask-user` 答案提供；
- **承诺实际状态**：在 `state/foreshadowing.md`，卷纲只写旧债/新债/禁揭；
- **场景/章数**：写到那里才知道；不预写章数。

## 章规划不在这里

每章写正文前，mate 拿一份这一章的**规划**（材料不在手上就 `task(planner)` 去要），`propose-plan` 交给用户拍板（带 `halt`），认可后 mate 自己照它写正文。

规划落在 `.talemate/plans/ch_<N>.md`——引擎工作区，不是作品文档；不参与 `list` / `search` / 不变量 / 设计指南。它由 harness 注入正文窗口，工具读不到。

## 序列进度

“写到这个序列的哪一步了”只有两个问法：

| 问法 | 答法 |
|---|---|
| **写到哪儿了** | 现算：`state/progress` 最后一节 + `chapters/` 章数 |
| **还剩什么** | 现读现判：规划者写下一章时读序列纲，顺手判断 |

**“还剩几章”不是答案。** 序列声明的是功能不是事件；“一节要写成几章，是写到那儿才知道的”——报个数就是编。
