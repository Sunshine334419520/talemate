# 情节层：卷纲与序列纲

> **职责**：回答"大纲由什么构成、一卷的纲/一个序列的纲各写什么、为什么没有整本大纲"。
> **读者**：要改 `framework/design_spec.ts` 里卷纲/序列纲那两条规范、或改情节层写入守卫的人。
> **对齐代码**：2026-10-25 · 规范在 `framework/design_spec.ts` 的 `SPECS`（按路径 glob 登记，具体者胜出）；章规划在 `framework/plan.ts`；规划者读卷/序列契约在 `prompts/planner.system.txt`，提交在 `prompts/tools/propose-plan.txt`
> 相邻：`design-docs.md`（四层与两段式落盘）· `characters.md`（另一个"主文档是目录"的层）· `state.md`（承诺的实际状态）· `chapter-planning.md`（章生产）· `roadmap.md`

## 一句话

情节层**只有两个尺度**：**卷**（一个完整阶段故事）和**序列**（卷内一个完整情节单元）。
没有"整本大纲"这个文档——它是**能算出来的东西**，存一份下来只会脱节。

两层都是**契约**，不是剧情梗概：卷契约约束"这一阶段结束时什么必须为真"，序列契约约束"这一小段结束时什么必须为真"。事件可以换，状态转移、转折的功能、承诺的兑现不能换。

## 为什么没有整本大纲

初版有一个 `design/outline/outline.md`，放着五格：一句话主线 / 开篇钩子 / 分卷方向 / 结局方向 /
伏笔与回收登记。推翻它，是因为**那五格没有一格真正需要一个"全书大纲"文档**：

| 旧那一格 | 现在的家 |
|---|---|
| 一句话主线 | core 的“一句话简介”——且那版更具体（谁 × 要什么 × 挡着什么） |
| 开篇钩子（前 3 章） | 就是头几章的章计划 |
| 分卷方向 | 就是卷纲本身 |
| 伏笔与回收登记 | 状态层 `state/foreshadowing.md`（见 `state.md`） |
| 结局方向 | core 的可选格——**用户想好了才填**；没想好就不该有这一格 |

判据是仓库一贯那条：**能算出来的东西不要存**（`CLAUDE.md` 的“Never hand-copy a list that can be
derived”、角色名单现算、`design-docs.md` 的“绝不缓存旧设定”）。全局观 = core 的"主角要什么" +
各卷卷纲"已经走到哪"——**它是每次规划新卷时现算的，不是存下来的。**

顺带一个对的结果：存下来的全本大纲一定会被写作推翻，而**脱节的缓存比没有更糟**——它会误导写手。

## 卷纲

`design/outline/vol_<N>.md`，六格。**一卷 = 一个完整阶段故事**：有自己的独立问题、不可逆变化、
收束，同时把主线往前推一步。卷长没有统一标准（网文结构卷常见 10–30 万字），边界由"什么不可逆地
变了"决定，不由字数决定。

| 格 | 一句话 |
|---|---|
| 本卷在全局的位置 | 独立故事问题 + 承接上一卷的差异/未决项 + 为什么是现在 + 主线增量 |
| 本卷目标与阻力 | 想要/需要 + 阻力类型与具体化身 + 对手目标/资源/反扑 + 升级轴 + 失败代价 + 本卷上限 |
| 本卷的承诺 | 旧债（兑现/推进/延期）+ 新债（预计何时还）+ 禁揭（3–5 条）+ 可选类型义务 |
| 本卷的节奏与情绪 | 主情绪 + 爽点轮换 + 中高潮/中点/低谷/卷末大高潮 + 喘息 + 卷首钩子 |
| 卷末状态 | 六轴状态 + 知识边界 + 卷末选择 + 代价/负债 + 旧债结清 + 新债/下一卷问题 + 刻意不变 |
| 本卷的序列 | 3–6 个功能 + 不可逆转折 + 线程 + 承诺 + 体量；因果链；卷末高潮落在哪一段 |

四条判据值得单独说，它们都是"改纲时会不会崩"的防线：

- **“卷末状态”写状态，不写事件。** “主角打败了 X”是事件，“主角从无人知晓变成沈家盯上了他”
  是状态。**事件可以换，状态必须保住**——这就是改纲的正确姿势：换事件、保状态。至少一轴不可逆；
  六轴都没变，这一卷只是一个大序列。
- **卷末高潮是选择，不是胜负。** 卷末要写清"两个都有代价的选项里，主角选了哪个、付出了什么"；
  只写打赢/打输，说明高潮还不是人物的高潮。胜利也要有代价——失去了谁、欠了什么、被谁盯上。
- **“本卷的序列”不写章号，也不展开每段。** 章数是**写出来的结果**，不是计划里的东西；
  细节写到那个序列再展开（各自一个文件）。序列的边界由"不可逆转折 + 出口状态不同"定义，
  两个序列出口状态相同，它们其实是同一个序列。
- **承诺账是计划，不是台账。** 卷纲只记旧债/新债/禁揭；实际埋在哪、收没收、有没有超期，
  归 `state/foreshadowing.md`。同一件事不抄两遍——抄两遍迟早说两套话。

`预估体量` 并进“本卷的序列”而不是单独一格：那一格本来就在讲"分几段"，段数与体量是同一件事。

**卷型骨架**（可选，不写进文档；混合是常态）：A 目标—阻力—升级型（玄幻/仙侠/都市异能/系统/竞技/复仇）、
B 地图—副本型（无限流/副本/悬疑/诸天/游戏）、C 关系—阶段型（女频古言/现言/宅斗/宫斗/职场/群像）。
骨架只做诊断，不是分类考试。

**卷末结算**：一卷写完时，先拿“卷末状态”与 `state/` 的实际状态对账：哪些轴变了、哪些旧债结了、
哪些新债开了、独立问题有没有回答。对不上就提议改卷末状态（`propose-design`，用户拍板），
不要带着旧计划写下一卷。下一卷的入口从实际卷末状态现算，不缓存全书分卷表。

## 序列纲

`design/outline/vol_<N>/s<序号>.md`。**整篇散文，不分小节**——一个序列本来就该一口气说完；
`list` 里只占一行 + 首句，靠的就是这个形状。

开头用行首标签写七件事（不必加 `##`），然后才是"大致怎么走"：

| 字段 | 写什么 |
|---|---|
| 功能 | 在卷里承担什么；推进哪条线程（全书主线/本卷目标/关系或支线）；兑现或埋下哪条承诺 |
| 问题 | 这一小段谁想要什么、谁挡着、失败会失去什么；必须能脱离整卷单独成立 |
| 入口 → 出口 | 入口只写关键前提（处境、资源、关系、谁知道什么、什么威胁悬着）；出口写结束时什么是真的，以及如何导致下一序列的问题；出口必须与入口不同 |
| 不可逆转折 | 至少一个，中长序列 2–4 个；从什么变成什么（行动/认知/关系/处境/力量/身份）；谁选择；代价 |
| 承诺 | 兑现哪条旧承诺、埋下哪条新承诺、什么不能提前揭 |
| 写法约束 | 哪几处不能写坏；世界规则/战力上限；哪些事件可以换 |
| 体量 | 预估字数范围，不写章数 |

`sections` 为空是**故意的**（与角色卡同路：形状全在 `guide` 里）。逼它分格是削足适履，
而且"必含 A、B、C"式的清单会把事件钉死——**只有功能稳定，事件随时可换**：

> 写功能（“给主角一个进内城的理由”），别写事件（“主角遇到老乞丐”）。

七字段里没有一条要求具体事件；入口/出口、转折、承诺都是状态。

`list` 里，**卷纲列它的六格，序列纲只给一行 + 首句**：

```
  outline/
    vol_2.md:
      - 本卷在全局的位置
      - 本卷目标与阻力
      - 本卷的承诺
      - 本卷的节奏与情绪
      - 卷末状态
      - 本卷的序列
    vol_2/s1.md（功能：主角混进沈家的夜宴，为的是拿到那本账册。）
```

判据：**只有当同一文档内部的小节会被分别读取时，目录才列小节。** 卷纲的六格会被单独
`read`（带 `section`）、单独 `edit`，所以列；序列纲整份读，所以不列。角色卡一人一行是同一个道理。

**事件仍然自由。** 契约只约束"进内城后谁知道什么、失去了什么"，不约束"通过谁进去"。
如果写作中发现更好的走法，**先改契约、再写正文**——改契约走 `propose-design`，用户拍板；
不能让正文静默推翻契约。

**写入一律走 `path`**：`design/outline/vol_<N>.md` / `design/outline/vol_<N>/s<序号>.md`。
没有第二个词表——`layer:"outline"` 那个参数连同那份层短名表一起删了（见 `design-docs.md`
的“寻址：只有路径”）。

**规范按路径登记**（`SPECS`），而且**更具体的模式胜出**：`design/outline/vol_*.md` 与
`design/outline/vol_*/s*.md` 同时命中一份序列纲，靠"模式更长者胜出"定胜负——**不靠表里的先后**。
取规范：`design-spec` 带 `path: "design/outline/"`（目录路径）拿两份，带某一份文档的路径拿其中一份。

## 章规划不在这里

一节要写成几章，是**写到那儿才知道**的。所以每章写正文前，mate 拿一份这一章的**规划**
（材料不在手上就 `task(planner)` 去要），`propose-plan` 交给用户拍板（带 `halt`，回合到此为止），
认可后**mate 自己照它写正文**。

**规划是序列契约的投影**：序列契约说"这一小段必须让什么为真"，章规划说"这一章怎么让它为真"。
每一章至少改变一项——信息、关系、资源、位置、认知；什么都不改变的一章是填充，应该合并或删掉。
章规划是一份**场景简报**：前情、这场戏、必须发生、不能提前兑现、章末读者问题，再附一张按序的产物清单；不写逐步节拍、字数或放大点。

**规划不落 `design/`**：它落在 `.talemate/plans/ch_<N>.md`——那是引擎的工作区，不是作品的一份
文档。`design/` 里没有它，`chapters/` 里也没有。判据、命名与清理策略见 `framework/plan.ts`，
整条链见 `design-docs.md` 的“章节生产”与 `chapter-planning.md`。

## 序列进度

"写到这个序列的哪一步了"有**两个问法，只有一个答得出来**：

| 问法 | 答法 |
|---|---|
| **写到哪儿了**（第几卷、第几个序列、最近一章推进了什么） | **现算**：`report.ts` 的 `outlineBrief` 读 `state/progress.md` 的最后一节报出来 |
| **还剩什么**（这个序列那几件事兑现了几件） | **现读现判**：规划者写第 N 章规划时本来就要读序列纲，顺手判断"这一段还剩什么、这一章钉哪一件" |

**"还剩几章"不是答案。** 序列纲声明的是**功能**不是事件，而"一节要写成几章，是写到那儿才知道的"——
所以章数与"这个序列兑现到哪了"之间没有换算关系，报个数就是编。

承诺的**实际状态**（已埋/已暗示/已回收/超期/放弃）从 `state/foreshadowing.md` 现读，不在卷纲或
进度卡里另存一份可勾清单。为什么不给序列纲加清单，见 `roadmap.md` 的“序列进度只报位置，不报剩余”。
