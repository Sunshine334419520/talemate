# 工具面重构：从「流程工具」回到「基础能力」

> **职责**：回答"我们的工具为什么长成这样、别家给的是什么、哪些该删、删了以后流程靠什么承载"。
> **读者**：要改工具面、agent 白名单、prompt、模式与测试的人。
> **状态**：2026-11-24 · 草案，尚未拍板，不含实现。
> **相邻**：`docs/agents.md`（现行工具表与触发矩阵）· `docs/design-docs.md`（两段式）· `docs/chapter-planning.md`（规划链）· `notes/资产优先工作台重构.md`（资产层）· `notes/小说Agent双轴矩阵.md`

## 0. 结论

**22 个内置工具里，11 个是"流程"而不是"能力"**：它们存在的理由是让模型按一条写死的写作流水线走，
而不是完成一个确定性动作。

目标是把工具面收回到 **11 个基础能力**：

```
read · list · search · write · edit · delete · task · ask-user · skill · webfetch · websearch
```

删掉：`design-spec`、`propose-design`、`apply-design`、`propose-plan`、`enter-draft`、`exit-draft`、
`enter-prose`、`exit-prose`、`confirm`、`recall`、`remember`。

> **分期（2026-11-24 追加）**：章节规划与规划后的"停"（`propose-plan` + halt）与考据缓存
> （`recall` / `remember`）先保留，不急着动；`enter-prose` / `exit-prose` 随规划链一起留。
> 这一期先删 6 个：`design-spec`、`propose-design`、`apply-design`、`enter-draft`、`exit-draft`、
> `confirm`，工具面回到 16 个（`list` / `search` 按 §9 换成 `glob` / `grep`，数量不变）。
> 11 个是终态。

流程不消失，换载体：**审阅交给权限/写前 diff，规划交给规划者 + 普通文件，正文规则交给 harness 状态，
结构知识交给资产定义与 skill，考据交给普通笔记文件。**

## 1. 别家给的是什么

### 1.1 Claude Code

官方工具表（[Tools reference](https://code.claude.com/docs/en/tools-reference)）的核心能力：

| 类别 | 工具 |
|---|---|
| 读 | `Read` · `Glob` · `Grep` |
| 写 | `Write` · `Edit` · `NotebookEdit` |
| 执行 | `Bash` / `PowerShell` |
| 搜索/联网 | `WebFetch` · `WebSearch` |
| 委派 | `Agent`（子代理） |
| 问用户 | `AskUserQuestion` |
| 知识 | `Skill` |
| 计划 | `EnterPlanMode` · `ExitPlanMode`（通用计划模式，不绑定任何业务） |
| 任务清单 | `TodoWrite` / `TaskCreate` 等 |
| 扩展 | MCP 资源、插件、`ToolSearch` |

其余是产品扩展（`Artifact`、`Cron*`、`Monitor`、`LSP`、`PushNotification`……），不是"基础能力"。
**它没有任何"写小说/写文档/做提案"的专用工具**。

### 1.2 reveric（小说 Agent）

`lib/shared/services/ai/tools.dart:3749-3788` 的工具目录：

```
Run · Read · Glob · Grep · Create · Write · Remove · Edit · Replace
GraphSearch · SpawnAgent · SendAgentMessage · StopAgent · ForkAgent
AskUser · SuggestNextAction · TodoWrite · AgentSkill
```

特征：

- **资源动词**：`Create` / `Write` / `Replace` / `Remove` 都是对"一份资源"的通用操作；
  具体是角色、章节还是大纲，由路径与类型决定，不是工具决定。
- **审批不在工具里**：改动先落 `working_change`，由权限/变更集决定接受还是回退。
- **流程在 prompt 里**：写作 → 审查 → 修正的闭环写在 `assets/prompts/agent/orchestrator.md`；
  规划没有专用工具，靠提示与任务清单（`TodoWrite`）。

### 1.3 两家的共同点

1. **工具回答"做什么动作"，不回答"现在处于哪个阶段"。**
2. **知识不进工具**：技能/模板/规则由 prompt、skill、仓储文件承载。
3. **审批是权限或变更集，不是工具调用**（Claude Code 没有 `confirm` 工具；reveric 没有 `propose-*`）。
4. **专用工具只在"没有别的表达方式"时出现**：reveric 的 `GraphSearch` 是因为关系图是它的一等数据；
   Claude Code 的 `NotebookEdit` 是因为 notebook 不是纯文本。

## 3. 为什么"流程工具"是错的

### 3.1 安全已经在写口，不需要第二道工具

`write` / `edit` 走 `write_ops`：算结果 → diff → 用户点头 → CAS + 原子写。**用户看过的字节 == 落盘的字节**
这条不变量在 `write_ops` 里，不在 `propose-design` 里。`propose-design` 只是"整篇 diff"的另一种入口；
它多出来的能力是"提意见后留在草稿模式里改"，而这件事用对话 + 再写一次就能完成。

**"模型夹带没看过的字节"在 `write` 上也不可能**：模型给的 `content` 正是 diff 里给用户看的那一份，
用户拒绝就不落盘。三向审阅不是安全边界，是交互舒适度。

### 3.2 知识不是动作

`design-spec` 返回的是"这种文档该有哪些小节"。它是**模板/规范**，该住在：

- 资产种类定义（`assets/kinds/*.json` 的字段）；
- 可选模板（新建资产时"空白 / 按模板"）；
- skill（"角色卡怎么写""卷纲怎么排"，按需加载）。

把它做成工具，等于每轮都要用一次工具调用取一份静态文本，还让"规范"与"资产定义"两处各说一套。

### 3.3 模式不是动作

`enter-draft` / `enter-prose` 回答的是"现在处于哪一段流程"。工具应该回答"做什么"。
一旦流程用工具表达，模型就会把"调了工具"当成"阶段完成"，而真正的判据（写没写、批没批）在文件与状态里。
Claude Code 的 `EnterPlanMode` 是这条规则的边界案例：它是**通用**的计划模式，不绑定章节、卷、设计文档；
我们如果要保留类似的"停下等拍板"，应该做成一个通用能力，而不是"第 N 章规划"。

### 3.4 每个流程工具都在收三重税

- **上下文税**：schema + description 每轮都在 system 里；
- **维护税**：prompt、工具实现、docs、测试、probe 补丁各一份；
- **误用税**：模型看到"propose-design"就会以为"写文档必须先提案"，哪怕用户只是要改一句话。

现行测试里有 90+ 处引用这些流程工具（`framework.test.ts`、`proposal_decision.test.ts`、`loop.test.ts`、
`write_ops.test.ts`、`eval_checks.test.ts`……），这就是"工具面绑住产品"的账单。

## 5. 三个需要拍板的缺口

1. **规划工件放哪、要不要一个通用的"停"**
   - `notes/plans/ch_N.md`（用户可见、git 有记录）需要把 `notes/` 加成一个根；或放进 `.talemate/plans`，
     但那样 `write` 必须允许写引擎工作区——两种都要在权限表里划一条。
   - 没有 `halt` 时，模型可能"摆完规划直接写正文"；因为正文也要 diff，安全不受损，但会多花一轮 token
     和一次无谓的提案。要不要加一个通用 `pause`（只回答"停在这里等用户"），是**交互决定**，不是安全决定。

2. **正文规则怎么注入**
   - 用状态：规划的 `approved` 且章节文件未出现 → 注入 `prose.system` + 文风卡（现在的窗口条件，
     只是不再需要工具切换）。
   - 或用 skill：让 mate 在写正文前 `skill("prose")`——但 skill 正文活不过压缩，这条已被否决过。
   - 推荐前者：**窗口由状态开，不由模型记得开**。

3. **考据笔记**
   - 首版删掉 `recall`/`remember`，researcher 只返回结论与出处；
   - 若实测"同一个事实反复查"成为痛点，再加 `notes/research/*.md`（普通文件 + `read`/`write`），
     而不是恢复一个专用工具。代价：`notes/` 要进语料根表（`talemate.json.corpusRoots`）或另有读口。

## 7. 防回潮：一个东西该不该做成工具

四条同时成立才做：

1. **它是一个确定性动作**：给参数就给结果，不需要它"想"；
2. **它不表达"现在处于哪一段"**：阶段归 prompt、状态、权限；
3. **它的输入不是某个文档种类的形状**：形状归资产定义/模板/skill；
4. **它不能由已有工具组合出来**：能组合的（读+写、问+写）不再加一层。

反例：`design-spec` 违反 3；`propose-plan` 违反 2；`confirm` 违反 4（权限已覆盖）；
`recall` 违反 4（笔记就是文件）；`enter-prose` 违反 2。

一句话：**工具是手，流程是协议。** 手越多越灵活，协议越少越清楚。

## 9. `list` 与 `search`：换成 `glob` + `grep`

### 9.1 `list` 现在实际提供了三样东西

| 提供的 | 例子 | 谁能替代 |
|---|---|---|
| **路径清单** | `design/characters/沈越.md` | `glob("design/**/*.md")` |
| **小节标题** | 角色卡的 `### 说话方式`、卷纲的六格 | `read`（截断时本来就会列小节与 offset）；或先读全文 |
| **领域摘要** | 角色卡「必有齐／待补：…／另有：…」、进度窗口、序列首句 | **UI 的文档树/状态卡**；模型读卡即可 |

前两样是"读的预处理"，第三样是**策略**（`framework/summaries.ts` 的 `SUMMARIES`：某种文档在目录里占哪一行）。
策略只该给界面用，不该进模型工具——模型看见"待补"摘要也不会比读一眼卡更准。

证据：`prompts/tools/list.txt` 的全部内容就是这三样；`anchor.buildIndex` 只被 `list` 工具与
`read` 的"没有找到文档，可用：…"提示使用；桌面左栏的文档树走 `docTree`，与 `buildIndex` 无关；
`/status` 走 `report.ts`，也无关。所以删掉 `list` 工具，**UI 与状态卡一行都不用动**。

**结论：删 `list` 工具，加 `glob`。** `buildIndex` / `summaries` 先留着当 `notFound` 的提示
（它不是模型可调的入口）；等 UI 需要展示摘要时再决定它们是留是删。

### 9.2 `search` 与 `grep`

现在的 `search` 是"字面量 + 路径前缀"：不能正则、不能按 glob 过滤、不能看上下文；
它返回的"文件 → 小节 + 行"是给文档寻址用的，不是通用搜索。

两家的做法一致：**Glob 找路径，Grep 找内容**（Claude Code 的 `Glob`/`Grep`；reveric 的
`tools_glob.dart` / `tools_grep.dart` 也是 `pattern + path + glob + output_mode + context`）。
所以把 `search` 换成 `grep`，同时补上 `glob`——这不是"加工具"，是把一个受限的搜索换成一个
通用搜索，外加它缺的那一半。

### 9.3 目标定义

**glob**

```jsonc
{
  "pattern": "design/**/*.md",   // 项目相对；* 不跨 /，** 跨 /，? 单字符
  "path": "design",              // 可选：限定起点前缀
  "limit": 200                   // 可选：默认 200
}
```

- 只返回文件路径（排序、去重），不读内容；
- 超过上限 → 结果截断并明说；
- 没有命中 → 空列表（不是错误）；
- 不含目录项（目录用路径前缀推断）。

**grep**

```jsonc
{
  "pattern": "伏笔",              // 正则；literal=true 时按字面量
  "path": "design/**/*.md",       // 可选：glob 过滤（也接受前缀，如 design/）
  "literal": false,               // 可选
  "ignoreCase": false,            // 可选
  "context": 0,                   // 可选 0–5：前后各几行
  "limit": 100                    // 可选：默认 100 条匹配
}
```

- 输出 `path:line: text`（类似 `grep -n`），每文件最多 20 条，超了标 truncated；
- 正则写坏 → 回一条模型可自纠的中文提示（不抛裸异常）；
- 不做"文件 → 小节"标注：那是文档寻址策略，模型拿到行号后自己 `read`。

### 9.4 迁移

- `read_tools.ts`：删 `list` / `search` 定义，加 `glob` / `grep`（同属读侧，不新开领域文件）；
- 新增 `framework/glob.ts`：标准 glob → 正则（`*` 不跨 `/`、`**` 跨、`?` 单字符），配 `enumerateDocs`；
  `framework/search.ts` 的 `scanDocs` 保留（删除引用检查、内部搜索仍用），`grep` 另走逐行正则；
- `ToolContext`：`listIndex` 留给 `notFound`；`searchDocs` 留给 `delete` 的引用检查；
  新增 `globPaths` / `grepDocs` 给工具用；
- prompt：删 `tools/list.txt` `tools/search.txt`，加 `tools/glob.txt` `tools/grep.txt`；
  `tools/read.txt` 里"Run list first"改成"use glob"；planner/researcher 的 system 同步；
- agent 白名单：`list`/`search` → `glob`/`grep`（mate / planner / researcher）；
- docs：`docs/agents.md` 工具表、`docs/architecture.md` 的取数口；
- 测试：`framework.test.ts` 的 list/search 用例、`read_limits.test.ts`、`corpus.test.ts`、
  `summaries.test.ts` 相应改写；新增 glob 语义（`*` vs `**`）与 grep（正则/字面量/上下文/截断）用例。

### 9.5 代价

模型做全项目盘点时，从"一次 `list`"变成"一次 `glob` + 若干次 `read`"。这是**用调用数换工具少**：

- 对 30 份文档的规模，glob 一次 + 读 5–10 份是正常量；
- 如果实测发现"为了看小节反复读全文"太贵，再给 `read` 加一个**通用**的 `headings: true`
  （只回标题，不算新动词），而不是把 `list` 加回来；
- 领域摘要（待补、进度窗口）从模型视野里消失是有意的：它们本来就是给人看的。
