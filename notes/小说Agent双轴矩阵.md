# 小说 Agent 的双轴矩阵：talemate 的现状，与按需求重推

> **读法**：第一部分是“talemate 现在长什么样”（描述）；第二部分是“如果从小说写作的需求出发，矩阵应该长什么样”（规范）；第三部分是“两者差在哪、怎么补”（诊断）。三部分可以分开读，合起来是一条完整的论证链。

---

## 0. 这份文档回答三个问题

1. **talemate 目前的实现，落在双轴矩阵的哪些格？**
2. **抛开 talemate 的既有设计，仅从“小说写作 Agent”出发，什么样的双轴矩阵是合理的？**
3. **两者差在哪？哪些差异是“没做”，哪些是“不该做”，哪些是“做错了”？**

这份文档不讨论“再多写几个功能”，只讨论：一个小说 Agent 要成立，**必须回答哪些问题**；这些问题的答案，落在矩阵的哪一格。

---

## 1. 坐标系：两份文档的标准

### 1.1 两根轴

- **纵轴：七脉（What）**——感知、记忆、推理、行动、反思、协作、治理。
  每一脉对应一种预算：注意力、连续性、不确定性、不可逆性、校正、分工、信任。
- **横轴：六式（How）**——链式、路由、并行、循环、层级、编排。
  每一式是一种**错误传播路径**：错误怎么从一步流到下一步。
- 7 × 6 = **42 格**。文档填了 **28 个模式**，留 **14 个空格**。
- 空格分三类：**结构性不成立**、**已被其他格覆盖**、**未来方向**。
- 选型三步：**ASSESS**（七脉各打 None / Light / Heavy）→ **ROUTE**（判主拓扑）→ **SELECT**（每个 Heavy 至少一个模式，第一版 3–7 个）。
- 评审五问：①七脉状态 ②每个 Heavy 落在哪个拓扑 ③主要错误传播路径 ④哪些格刻意留空、理由 ⑤v1→v2 升级路径。

一句话：**矩阵不是功能清单，是“花哪种资源 × 错误怎么流”的地图。**

### 1.2 本文档怎么用这张矩阵

第一部分用“**占格**”描述 talemate——它有哪些模式、落在哪。
第二部分用“**问题**”重推——一个写作单元必须回答什么，七脉各承担哪一类。
第三部分用“**问题**”量 talemate——它能回答哪些、答不了哪些。

“占格”回答“它有什么”；“问题”回答“它能不能写出这一章”。后者才是小说 Agent 的判据。

## 2. 第一部分：talemate 现有实现的矩阵

### 2.1 逐脉占格

| 脉 | 具体机制 | 坐标 | 格数 | 说明 |
|---|---|---|---|---|
| **感知** | 语义压缩（compaction：一条 summary + recent）；上下文分诊（`core.md`/`wiki/world.md` 常驻，其他按需切片） | 感知×链 / 感知×路由 | 2 | 分诊按“文档类型”分，不按“问题”分；没有“读者状态”“作者意图”的取数口 |
| **记忆** | 检索增强（`read`/`list`/`search`/`recall`）；分层保留（core/world 常驻，cards/state 按需，prose 全文）；进度追踪（`state/progress` 7 章窗口 + 序列契约 + `.talemate/plans`） | 记忆×链 / 记忆×层 / 记忆×编 | 3 | 覆盖 canon 和 state；intent、craft、reader 无载体 |
| **推理** | 场景简报（planner：前情、这场戏、必须发生、不能提前兑现、章末问题） | 推理×链 | 1 | 只有“后果”一类；章型、动机、分支无模式 |
| **行动** | 工具调度（`write`/`edit`/`delete`）；规划执行（`propose-plan` 的按序产物清单）；护栏三明治（permission 前置 + invariants 后验） | 行动×路 / 行动×编 / 行动×层 | 3 | 有可逆性控制；但没有把“规划→正文→状态→回看”写成一条有 schema 的提示链 |
| **反思** | 无 | — | 0 | 只有文档形状不变量，没有内容取证 |
| **协作** | 层级委派（planner / researcher，depth 1，只读） | 协作×层 | 1 | 只有“取证”型委派，没有“多视角取证”的扇出 |
| **治理** | 渐进承诺（`propose-design`/`propose-plan` + halt）；审批门控（permissions 五类，deny 单调）；可观测性（`events.jsonl`/trace）；爆炸半径（三个根 / 权限 pattern / depth cap） | 治理×链 / 治理×路 / 治理×编 / 治理×层 | 4 | 强，且自洽 |
| **合计** | | | **14 / 42** | |

**一处坐标修正**：早先我把 planner 记成“推理×编排”，这是不准确的。
planner **不派发**，只交回一份场景简报；它是“把这一章必须发生的事拆成一条链”，所以是 **推理×链**。
“派发产物清单”才是 **行动×编排**。
把两者混成一格，会误以为 talemate 已经有“推理编排”，其实它只有“行动编排”。

### 2.2 剖面

- **14 / 42**：感知 2、记忆 3、推理 1、行动 3、反思 0、协作 1、治理 4。
- 主拓扑是 **链式**：顺着“规划→正文→状态”往下走，门在 `propose-plan` / `propose-design`。
- 一句话：**talemate 是一条带门、带护栏、可回放的写作链，不是一个会反省的写作者。**

这个形状不是偶然。它的产品宪法——用户当主编、不做评判 Agent、不做导演 Agent、正文不派子代理——直接决定了：**治理重、反思零、协作薄**。

### 2.3 四道思考题（对 talemate 的回答）

**① 七脉打分，哪一脉最被低估？**

- 感知 Light、记忆 Light、推理 Light、行动 Light、**反思 None**、协作 Light、治理 Heavy。
- 最被低估的是 **感知**。不是“它读文件读得少”，是“它的取数口按文档类型分，不按这一轮必须回答的问题分”。于是“读者此刻知道什么”“作者否过什么”这类没有文件的问题，根本进不了取数流程。

**② 章节生产拆坐标：是推理×编排，还是协作×层级？**

- 都不是单独一个。准确拆法是：
  - 协作×层级（planner 被委派）
  - 推理×链（场景简报）
  - 治理×路由（权限/审批）
  - 行动×编排（产物清单）
  - 记忆×编排（进度）
- **不是推理×编排**：planner 不派发，只交简报；派发的是行动。

**③ 给一个 Loop 写停止条件——`runLoop` 的停止条件是什么？**

- 无 tool call / `halt` / 达 steps 上限 / 子代理最后一步撤工具。
- **“质量”不是停止条件**。质量是评估信号，不是停机判据。把“质量够了”写成停止条件，等于把停机权交给模型的自评——那是评判 Agent 的变体。
- 子代理用“最后一步撤工具”把停止条件**机制化**：不是“请你自己判断够了”，而是“工具没了，你只能把已有材料写成结论”。

**④ 判一个空格的性质：反思×并行是什么？**

- **制度性留空（产品性空）**。不是结构性不成立，也不是已被覆盖，而是产品宪法禁止“多 critic 投票裁决”。
- 这类空格是“故意不填”，不是“还没填”。判据：填了它，产品会变成另一个产品。

### 2.4 五问评审（对 talemate）

1. **七脉状态**：见 2.3。
2. **每个 Heavy 的拓扑**：治理 Heavy → 链（渐进承诺）+ 路由（门控）+ 编（可观测）+ 层（爆炸半径）。
3. **主要错误传播路径**：链式（错误级联）为主；治理路由是唯一的分派点；没有并行/循环，所以没有聚合错误和复合错误。
4. **刻意留空的格**：反思整行、协作×并行/循环/编、行动×并行/循环。理由分别是产品宪法、单写手、单 canon。
5. **v1→v2 升级路径**：见第三部分 4.4。

### 2.5 现状的三个特征

**特征一：带门的链。**
主拓扑是链式，门在 `propose-plan`/`propose-design`。错误沿链级联，门只拦“没拍板”，**不拦“写得不对”**。所以门很硬，内容很软。

**特征二：反思制度性空。**
不是“没来得及做”，是“把反思等同于评判”。为了不做评判 Agent，把“取证”也一起删了。结果：没有任何机器可读的“这一章违反了哪条契约”。

**特征三：跨行环无坐标。**
“写作中浮现新点子 → 改企划 → 影响下一章”是记忆×编排 + 治理×链 + 感知×路由的复合环。矩阵的格是“单脉单式”，这个环没有一格能单独装下它。
这不是矩阵的缺陷，是“一个模式只描述一个动作”的边界；复合环要用**模式组合**描述，不能硬塞进一格。

### 2.6 现状暴露的问题（预告）

**不是“少占了 13 格”，是“有 6 个写作必须回答的问题没有答案”。** 第三部分展开。

## 3. 第二部分：按需求重推

### 3.1 方法：对象 ≠ 载体

先分清两件事：

- **载体**：文件、账本、对话历史、向量库。`design/wiki/world.md`、`state/characters/`、`chapters/`、`research/` 都是载体。
- **对象**：这本书**必须保持或决定的东西**——世界规则、谁此刻知道什么、作者否过什么、读者现在期待什么。

同一个对象可以换载体；同一个载体可以装多个对象。

- `design/wiki/world.md` 是载体，对象是“世界规则”。
- `state/characters` 是载体，对象是“谁此刻知道什么”。
- `chapters/` 是载体，对象是“已经成立的 canon”。

**从载体倒推的后果**：你会得到“感知＝读 wiki”“记忆＝存 state”。于是“读者状态”“作者否决”“品味”这些**没有文件的对象**，永远进不了矩阵。
**从任务出发**：你会问“这一场戏需要我知道世界的哪一条规则，最便宜、最可靠的来源是 wiki、上一章正文，还是直接问作者？”

正确的推导链：

> **写作任务 → 必须回答的问题 / 必须保持的连续性 / 必须解决的不确定性 → 七类能力 → 载体 → 模式。**

这也解释了这个项目自己的一条原则：**能算的不要存**。对象是 truth，载体可以是 cache。倒推法永远推不出这条——它只会把 cache 当成 truth。

### 3.2 推导的起点：一个“写作单元”要成立什么

一个写作单元（一章、一场戏、一次设计对话、一次考据）的任务是：

> 在**作者意图**和**既有 canon** 的约束下，产出下一段**可以成为 canon** 的文本（或设定），并让它在**读者**身上产生受控的效果。

三个硬约束，缺一不可：

1. **连续性**：新单元不能和已成立的 canon 矛盾。
2. **意图**：新单元必须是“作者认领的那本书”的一部分，不是另一本。
3. **读者**：新单元要控制读者此刻知道什么、期待什么、害怕什么。

**七脉就是让这三条成立所需的七类能力**，不是七个文件夹。

### 3.3 七脉逐脉重推

#### 3.3.1 感知：不是“读哪些文件”，是“让哪些答案在场”

**它的目的**：让这一章“合理且好”，不是“读到材料”。所以它先要判断：**“合理且好”需要哪些答案？**

**五步判断：**

1. **定单元**：这一轮是哪种单元？过渡章、高潮章、设计对话、考据？——不同单元要回答的问题不同。
2. **定问题**：这种单元必须回答哪些问题？——谁在场、各自要什么、谁挡谁、什么不能提前兑现、读者此刻知道什么、哪些事实不能编、这本书的声音是什么。
3. **定来源**：每个问题**最便宜、最可靠**的来源是哪一个？常驻、现读、现算、问作者、查外网。
4. **定够不够**：能回答到可以动笔吗？不能就再读；能就停。**感知必须有一个“够了”的判据**，否则要么读太少（OOC），要么读太多（关键卡被淹）。
5. **定过期**：canon 改过之后，手上这份答案还成立吗？

**对象是“答案”，不是文件。**
同样是“写一场夜宴”，需要的问题可能是：谁在场？谁知道账册在谁手里？这个朝代的夜宴吃什么？读者此刻怀疑谁？——四个问题，四个不同载体，没有一个叫“读一遍世界观”。

**失败四型**：答案缺席（OOC）、答案被淹（读太多）、答案过期（用了旧设定）、来源错了（该看正文却看了 wiki）。

**模式：** 语义压缩（把长篇历史压成工作简报）、上下文分诊（按问题选来源）、渐进发现（读→发现缺口→再读，带“够了”的停止条件）、多模态融合（多篇文风样本融成一个声音简报）。

**与 talemate 的差**：它的取数口按“文档类型”分（core/wiki/cards/state/prose），不是按“问题”分；所以“读者知道什么”没有取数口。

#### 3.3.2 记忆：不是“存哪些文件”，是“哪些连续性必须跨单元保持”

**四步判断：**

1. **定连续性**：这条信息属于哪一种？canon / state / intent / craft / reader。
2. **定半衰期**：常驻、按需、归档？
3. **定真值**：它是“现在”，还是“来历”？（state 是现在，prose 是来历；两者冲突时，prose 往往是真值）
4. **定召回/遗忘**：写之前要主动召回，还是已经过期该丢？

**五种连续性：**

| 连续性 | 必须保持什么 | 失效表现 | 常用载体（不是对象） |
|---|---|---|---|
| **canon** | 世界规则、事实、名字、术语 | 吃书、规则失守 | wiki、正文、术语表 |
| **state** | 谁在哪、谁知道什么、欠什么 | 前后矛盾 | state、正文 |
| **intent** | 作者要什么、否过什么、为什么 | 写偏、重复被否 | 对话、否决记录、品味档案 |
| **craft** | 哪种写法在这本书里成立 | 重复犯错、声音漂移 | 失败日记、经验回放 |
| **reader** | 读者知道什么、期待什么、被欠什么 | 信息差失效、期待透支 | 读者账（通常没有） |

**talemate 的 `state/` 只覆盖了 state 和一部分 canon；intent 和 craft 基本没有载体；reader 完全没有。**
这不是“少一个文件”，是**少三种连续性**。

**模式：** 检索增强（canon/state 现取）、分层保留（按半衰期分层）、进度追踪（书到哪了）、失败日记（craft/intent 的反面）、**品味档案**（intent 的正面：作者一贯接受/否决什么，区别于“选定的文风”）、**读者账**（reader 的载体）。

其中**品味档案**和**读者账**是小说特有的两个记忆模式。
通用 Agent 没有“作者的品味”和“读者的状态”这两个一等连续性对象，所以文档的 28 个模式里没有它们。

#### 3.3.3 推理：不是“planner 怎么拆”，是“哪几类不确定性必须被解决”

**四步判断：**

1. **定不确定性**：章型 / 分支 / 动机 / 后果，哪一类？
2. **定深度**：这一类需要多深？过渡章一稿就够，卷末高潮要分支比较。
3. **定停止**：什么时候停止探索、提交一个答案？
4. **定代价**：如果这个答案错了，哪一层会坏？

| 不确定性 | 问题 | 模式 |
|---|---|---|
| **章型** | 这一章是过渡、铺垫、小高潮还是卷末高潮？该用多深的推理？ | 复杂度路由 |
| **分支** | 这个选择走 A/B/C，各自的后果是什么？ | 并行探索 |
| **动机** | 这个人为什么这么做？符合他的怕和底线吗？ | 迭代假设 |
| **后果** | 这一章必须让什么为真？ | 思维链 |

talemate 只有第四类（planner 的场景简报）。前三种不是“没来得及做”，是**没意识到推理需要模式**——它把推理押在模型的 raw reasoning 上。

#### 3.3.4 行动：不是“有哪些工具”，是“哪些 canon 变更必须发生，及其不可逆性”

**四步判断：**

1. **定突变**：这次改的是 canon 的哪一部分？正文、设定、状态。
2. **定可逆**：错了能不能回滚？谁看过？
3. **定下游**：改完之后，哪些章节、文档会读到它？
4. **定顺序**：先立人还是先写字？先规划还是先考据？

**单位是 canon mutation，不是 tool call。**
一次 `edit` 可能同时改了人物的处境和一条伏笔；一次 `write` 可能把整章 canon 定下来。工具是动作，canon 变更才是后果。

**模式：** 提示链（规划→正文→状态→回看，每步有 schema）、工具调度（选哪种突变）、护栏三明治（前置权限→写→后置不变量）、规划执行（产物清单）。

**行动×并行是结构性空**：单 canon、单写手。并行写会造出互相冲突的 canon。

#### 3.3.5 反思：不是“谁来评审”，是“产物与哪些契约可能不一致，怎么便宜地发现”

**四步判断：**

1. **定契约**：产物对哪些东西负责？plan、card、world、voice、reader。
2. **分客观/审美**：哪些偏差机器可查，哪些只能人判？
3. **定证据**：证据怎么摆，人的裁决才便宜？
4. **定修复**：客观偏差修不修，修到什么程度停？

| 维度 | 产物对什么负责 | 判定性质 |
|---|---|---|
| **契约** | 必须发生 / 不能提前兑现 | 客观（可对照） |
| **人物** | 底线 / 说话方式 / 知识边界 | 半客观（卡是合同） |
| **世界** | 规则 / 术语 / 战力上限 | 客观 |
| **文风** | 视角 / 语域 / 节奏 | 审美（人判） |
| **读者** | 此刻该知道 / 该期待什么 | 半客观（可推演） |

**反思这一行的关键，是把“判定”从“取证”里拆出来。**
证据审只报“这一行违反了哪张卡的哪一条、这个承诺第 7 章已经兑现、这个词不在术语表”，不打分、不给改法；场景检查单按场景类型路由；客观自愈只修客观错误；经验回放记本书里“哪种开场被接受、哪种被否”。
四个都不做裁决，所以和“人是主编”不冲突。

talemate 把反思等同于评判，于是整行删掉，连“取证”也一起删了。

#### 3.3.6 协作：不是“有哪些子代理”，是“哪个上下文装不下，切开后声音还在不在一个人手里”

**三步判断：**

1. **定装不下**：哪个上下文装不下？读一堆材料、查外网、多视角取证。
2. **定声音**：切开之后，笔还在一个人手里吗？
3. **定产出**：子代理交回的是**结论**还是**材料**？

**模式：** 层级委派（planner/researcher，depth 1，只读）、扇出聚合（世界/人物/承诺/文风四路取证）、交接链（世界→人物→情节→场景→文风，接力——这是**另一个产品形状**，会切碎声音，和“一个 mate 自己写正文”冲突）。

**小说协作的边界是“谁握笔”**：planner/researcher 可以切开，正文不能；扇出聚合切的是“取证”，不是“写作”。

#### 3.3.7 治理：不是“有哪些权限”，是“作者怎么保持作者身份”

**四步判断：**

1. **定半径**：这次变更影响多少下游？
2. **定签字**：谁必须看过才能落盘？
3. **定回滚**：错了能不能还原？
4. **定账**：谁在何时改了什么，留得下来吗？

**模式：** 渐进承诺（提案→拍板→落盘）、审批门控（权限五类）、爆炸半径（三个根/权限 pattern/depth cap）、可观测性（事件/trace）。

talemate 这一脉是强的，不需要补。

### 3.4 六式的小说版错误传播

| 拓扑 | 小说里的错误怎么流 | 典型失败 | 工程动作 |
|---|---|---|---|
| **链式·传** | 上一步的假设立即成为下一步的 canon；早期分解错，全链白费 | 场景简报漏了“必须发生”，正文写得再好也偏 | 缩链、每步 schema、简报先对契约 |
| **路由·选** | 章型/权限/取证类型选错，后面的处理器再对也白费 | 把过渡章当高潮章写，或反之 | 路由可观测、可回退；先小后大 |
| **并行·撒** | 多路分支/多视角取证，merge 决定质量 | 三路取证互相矛盾，没有人仲裁 | 先定 merge 规则，再撒 |
| **循环·转** | 改稿/自愈/迭代假设；错误复合，停止条件不清就发散 | 越改越远，或停在第一个能自圆的版本 | 停止条件、评估信号、每轮改动幅度 |
| **层级·分** | depth 1 的委派；隔离失守/权限继承过宽/子代理失败雪崩 | 子代理读到了不该读的，或空结果被当成“答了” | 类别拒、depth cap、空结果显式化 |
| **编排·协** | 拆错任务边界；产物清单漏一环，整章返工 | 规划里没有“状态回写”，写到一半发现账对不上 | 验证 plan、按序产物、每步可检查 |

### 4.1 差异总表

### 4.2 用“问题”量 talemate

矩阵的价值不是数格子，是**列问题**。一个小说 Agent 合不合理，看它能不能回答一个写作者必须回答的问题。

| 写作单元必须回答的问题 | talemate 靠什么回答 | 判断 |
|---|---|---|
| 这本书要什么？ | 作者对话 + `core` 一句话 | 有 |
| 这一章要推进什么？ | 序列契约 + planner | 有 |
| 此刻世界是什么样？ | wiki + 正文 + 章末回看 | 部分（规则散落） |
| 此刻人物是谁？ | 卡 + `state/characters` | 有 |
| 故事到哪了？ | `state/progress` 7 章窗口 | 部分（窗口有限） |
| **读者此刻知道什么、期待什么、被欠什么？** | **无** | **缺** |
| **作者否过什么、为什么？** | 对话；压缩后丢失 | **缺** |
| **这一章是什么型、该多深？** | **无**（所有章同一深度） | **缺** |
| **这个人为什么这么做？** | 模型 raw reasoning | **无模式** |
| **这个选择走哪条分支？** | **无**（一条线写下去） | **缺** |
| **这一章和契约/卡/世界/文风哪里不一致？** | 人的眼睛 + 文档形状不变量 | **缺** |
| 哪些外部事实不能编？ | researcher + 考据本 | 有 |
| 这本书的声音是什么？ | 文风卡 + prose rules | 有 |
| 谁批准、能改哪、留什么账？ | permission + `write_ops` + events | 有（强） |

**8 个有答案，6 个没有。**
缺的六个不是“少占了 13 格”，是**六个写作必须回答的问题没有答案**：

- **读者**（记忆×编排）——没有读者账，信息差和期待只能临时处理。
- **作者否过什么**（记忆×循环/层级）——没有失败日记和品味档案，同一个修正隔十几章再犯。
- **章型**（推理×路由）——过渡章和高潮章同一深度，节奏扁平。
- **动机**（推理×循环）——人物为什么这么做，一次成型，没有试错。
- **分支**（推理×并行）——卷末选择没有 A/B/C 比较。
- **偏差**（反思×链）——没有机器取证，用户是唯一的质检。

这六个问题，正好落在**记忆（intent/craft/reader）、推理（章型/动机/分支）、反思（偏差）** 上。治理和设定那两块，talemate 答得很好；它缺的是“这本书的连续性”和“这一章对不对”。

### 4.3 六条诊断

**诊断一：反思＝评判（元错误）。**
为了不做“批评者 Agent”，把“取证”也删了。代价：没有任何机器可读的“这一章违反了哪条契约”。
最小修法：加一个只读取证工具——正文落盘后、状态回写前，对照 plan/card/world/voice 报“违反哪条”，**不打分、不给改法、不是新 agent**。

**诊断二：推理只有一格。**
只有“后果”（planner 的场景简报），没有章型、动机、分支。代价：所有章同一深度；人物动机一次成型；卷末没有分支比较。
最小修法：给 plan 加 `chapter_type`（过渡/铺垫/高潮），按型决定规划深度；动机用迭代假设，分支用并行探索（v3）。

**诊断三：没有失败日记。**
作者的否决活在对话里，压缩只留 assistant 的 text，tool 结果不进摘要，所以**否决理由活不过一次压缩**。代价：同一个修正隔十几章再犯。
最小修法：加 `state/failures.md`，每次否决记一条（第几章/否了什么/为什么），规划窗口注入。

**诊断四：没有读者账。**
读者此刻知道什么、期待什么、被欠什么，没有载体，只能临时从正文推。代价：信息差失效、期待透支。
最小修法：加 `state/reader.md`，每章后追加“读者现在知道/期待/被欠”，下一章规划读取。

**诊断五：协作只有层级，没有扇出。**
planner/researcher 是“取证”的雏形，但没有“世界/人物/承诺/文风四路同时取证”的扇出。代价：取证是串行的，慢且容易漏。
最小修法：扇出聚合（v3）；先在反思×链里做“四维取证”，不急着上多 agent。

**诊断六：治理先于反思。**
内圈（感知/记忆/推理/行动）没走完，就上了外圈（治理）。结果是“安全但写偏”：能防住模型乱改，防不住模型写错。
这不是“治理做得太多”，是“反思做得太少”。修法是补反思，不是拆治理。

### 4.4 如果重来：v1 / v2 / v3

**v1（6 个模式，3–7 之内）：**

1. **上下文分诊**（感知×路由）——先解决“这一轮该取什么”。
2. **分层保留**（记忆×层级）——canon 常驻，state 按需，prose 全文。
3. **思维链**（推理×链）——这一章必须让什么为真。
4. **规划执行**（行动×编排）——按序产物，每步可检查。
5. **证据审**（反思×链）——只报偏差，不打分。
6. **审批门控**（治理×路由）——落盘前有人签字。

理由：三条硬约束各至少一个（连续性：分层保留；意图：上下文分诊 + 审批门控；读者：证据审里的 reader 维度）；反思只做取证；治理只做门；6 个在 3–7 内。

**v2（+3）：**

- **失败日记**（记忆×循环）——作者的否决要活过压缩。
- **复杂度路由**（推理×路由）——章型决定推理深度。
- **读者账**（记忆×编排）——信息差和期待要有载体。

理由：这三个最直接决定“写偏”，而不是“写得不够好”。

**v3（其余）：**

- 扇出聚合（协作×并行）、品味档案（记忆×层级）、客观自愈（反思×循环）、经验回放（反思×层级）、渐进发现（感知×循环）、并行探索（推理×并行）、迭代假设（推理×循环）。

理由：这些是“写得更好”，不是“写得成立”。先成立，再变好。

### 4.5 最小修正 talemate（不换产品宪法）

这五条都不新增 agent，不新增评判，不改“用户当主编”：

1. **拆 `propose-plan`**：场景简报（推理×链）+ 产物清单（行动×编排）。现在两者混在一份里，用户一次拍板两件事。
2. **加证据读取**（反思×链）：正文落盘后、状态回写前，只读一遍，报“违反哪条”；不改写、不打分、不是新 agent（一个 tool）。
3. **加 `state/failures.md`**（记忆×循环）：每次否决记一条；规划窗口注入。
4. **加 `state/reader.md`**（记忆×编排）：每章后追加“读者现在知道/期待/被欠”；下一章规划读取。
5. **给 plan 加 `chapter_type`**（推理×路由）：过渡/铺垫/高潮；按型决定规划深度和取证清单。

如果只能做一条：**做第 2 条**。它把“用户是唯一质检”变成“机器先取证，用户再裁决”，而且不引入任何评判角色。

## 5. 结论

- **七脉不是一个组织里的七个部门，而是一类“让这一章成立”的能力。** 判断先于模式：先问“这一轮必须回答什么”，再问“用哪个模式去答”。
- **对象 ≠ 载体。** 设定、状态、正文是载体；必须保持的连续性、必须回答的问题、必须解决的偏差，才是对象。从载体倒推，只能得到 talemate 的镜像；从任务倒推，才能得到小说 Agent 的矩阵。
- **矩阵的用处是列问题，不是数格子。** talemate 的骨架（带门的链）是对的；它的问题不在“少占了哪些格”，在“有六个问题没有答案”——读者、品味、章型、动机、分支、偏差。
- 这六个问题里，**五个都不是“加一个 agent”能解决的**：读者账和品味档案是记忆，章型路由和分支探索是推理，偏差取证是反思。它们是**能力**，不是**角色**。这也解释了为什么“不加评审 agent”是对的，而“不加取证能力”是错的——两者不是一回事。
- 一句话：**治理让 agent 可信，记忆和反思让 agent 可读；talemate 已经可信，还没可读。**

## 附录 B：术语

| 术语 | 含义 |
|---|---|
| **对象 / 载体** | 对象是必须保持/决定的东西（规则、知识边界、品味、读者状态）；载体是存放它的文件/账本/对话。同一个对象可以换载体 |
| **连续性** | 跨写作单元必须保持的东西：canon / state / intent / craft / reader |
| **取证 / 判定** | 取证＝报“违反了哪条契约”，机器可做；判定＝说“这章好不好”，人做 |
| **带门的链** | 主拓扑是链式，门在提案/拍板处；门拦“没拍板”，不拦“写得不对” |
| **跨行环** | 一个动作同时落在多脉多式上（写作→新点子→改企划→下一章），不能塞进单格，要用模式组合描述 |
| **产品性空** | 空格不是“没做”，是“做了会变成另一个产品”（如多 critic 投票） |
| **结构性空** | 空格在结构上不成立（如感知×层级：感知不是委派问题） |
| **覆盖性空** | 空格已被另一格覆盖（如推理×编排被推理×链 + 行动×编排覆盖） |
| **未来性空** | 空格是合理方向，但当前产品不需要（如记忆×并行） |
